Экран **`/purchase.html`** — планирование закупок. Источник истины базовых полей — таблица **`ms_export`** (синк МойСклад). Список на сервере строится запросом в MySQL с **`LIMIT`/`OFFSET`** и сортировкой в SQL; тяжёлое обогащение строк выполняется **только для текущей страницы** (см. `GET /api/purchase` в `api.md`). Дополнительные **редактируемые поля** (Неснижаемый остаток Датагон, Кратность товара, Мин. остаток сч.как 0) хранятся в отдельной таблице **`dg_purchase_overrides`** и **не теряются** при пересинке МС. Поле **`proposed_min_stock`** в той же таблице по-прежнему участвует в расчёте «Предлагаемый нес.ост.» и доступно в **`GET/POST /api/purchase`**, отдельной колонки на экране нет.

## Что показывается на странице

По умолчанию — **только активные складские позиции** МС (без архива и без комплектов):

- `is_archived = 0`,
- `stock_position = "да"`,
- `type ≠ "Комплект"`.

Эти три условия можно ослабить через селекторы «Архивные» / «Складская позиция». Отдельно — селектор **«Перестали сотрудничать»** (поле `ms_export.no_longer_cooperation`): по умолчанию **Нет** (в МС не «Да» — пусто, «нет», иное); также **Все** или **Да** (в МС «Да»). Дополнительно — поиск по коду/артикулу/названию/поставщику, отдельный фильтр поставщика и селект **«Доп. фильтр»** (один режим: только с остатком &gt; 0, комплекты, нулевой остаток, нулевой без ожидания, без кратности, неполная упаковка).

## Колонки таблицы

| Колонка | Источник | Поведение |
|---------|----------|-----------|
| Артикул | `ms_entity_details.payload_json.article` | из raw карточки МС |
| Наименование | `ms_export.name` — **ссылка на** `/product.html?code=…` по тексту названия; **🕘 Лог** журнала закупок **в одной строке справа от названия** (как на габаритах); внутренний код в `title` ссылки; бейдж **Архив** при необходимости; сортировка по колонке в UI = **`sort_by=code`** на API |
| Поставщик | `ms_export.supplier` + `supplier2` | если совпадают (без учёта регистра/пробелов) — выводится один; если различаются — `Поставщик1/Поставщик2` |
| Проработка цены / коммент | `ms_export.price_comment` | пользовательское свойство МС (как на выгрузке МойСклад); длинный текст в `title` |
| Закупочная цена | `ms_export.buy_price` | формат «12 345,67 ₽» |
| Неснижаемый остаток | `ms_export.min_stock` | из МС, прочерк если не задано |
| Предлагаемый нес.ост. | расчёт на сервере / `dg_formula_proposed_cache` | `formula_proposed_min_stock` — та же формула, что на карточке товара; в списке без bundle-warmup; при наличии кэша (`formula_fp` + `data_rev`) — из LEFT JOIN; иначе enrich страницы. Не редактируется; `dg_purchase_overrides.proposed_min_stock` — опорный неснижаемый для шагов формулы |
| Автоматизация цены | `ms_export.automation_price` | как в МС; **скрыта** при доп. фильтре «К закупке» и при переходе с «Поставщики» (`to_buy=1`) |
| **К закупке** | расчёт на сервере | `to_purchase_qty` — только в режиме «к закупке»; `max(0, неснижаемый остаток МС − остаток − ожидание)` — **только** `min_stock` из МойСклад, не «Предлагаемый нес.ост.» |
| **Нес.остаток Датагон** | `dg_purchase_overrides.min_stock_dg` | **редактируемое** — input в ячейке, сохраняется по `change`; **не** входит в опорный baseline формулы; если задано число **> 0**, отображаемый «Предлагаемый нес.ост.» **не ниже** этого значения |
| **Кратность товара** | `dg_purchase_overrides.multiplicity` | **редактируемое** |
| Кол-во в упаковке | `payload_json.packagings[0].quantity` или `pack_qty_manual` | автоматически по карточке; ручной override имеет приоритет |
| Остаток | `ms_export.stock` | текущий остаток МС |
| Ожидание | `ms_entity_details.payload_json.inTransit` | подставляется при **полном синке МС** из **`report/stock/all`** (в ответе `entity/product` поле часто отсутствует); «—», если в отчёте нет ожидания |
| **15 … 365** (прод., шт) | `GET /api/purchase` | сумма проданного за N календарных дней (`d_15a` … `d_365a` с шагом окон 15+), проведённые отгрузки, прямой код + эквивалент через комплекты (для **комплекта** — только прямые продажи кода комплекта) |
| **15 … 365** (дн. нет) | `dg_product_zero_stock_log` | число **разных календарных дат** с нулевым остатком за N дн.; поля `d_15b` … `d_365b` |

## Редактируемые поля: как сохраняются

Каждое редактируемое значение сохраняется **сразу при изменении** через `POST /api/purchase/override` — это одиночное действие пользователя (по правилу `datagon-table-filter-apply.mdc` оно допустимо без кнопки «Применить»).

- Жёлтый фон ячейки — идёт сохранение.
- Зелёный фон — успешно сохранено и значение **верифицировано** из БД (формат: «5», «5.5», «10»).
- Красный фон — ошибка (наводите на ячейку — там будет текст ошибки).
- **Esc** в ячейке — отмена изменений; **Enter** — подтверждение и снятие фокуса.
- Очистить значение — стереть текст и нажать Enter / Tab; в БД ляжет `NULL`.
- **Журнал по полю** — наведение на ячейку override (без отдельной иконки): всплывающая подсказка с последними тремя записями `dg_purchase_overrides_log` для этого кода и поля (как hover-журнал на `/exports-dimensions.html`).

Карточка «Фильтры и действия» соответствует эталону `/moysklad.html`:

- **Умный поиск** — по код / артикул / наименование / поставщик 1/2.
- **Поставщик** — отдельное поле фильтра (case-insensitive, по `supplier` и `supplier2`).
- **Архивные** — `Только активные` (default) / `Только архив` / `Все`.
- **Складская позиция** — `Только Да` (default) / `Только Нет` / `Все`.
- **На странице** — 50 / 100 (default) / 200 / 500.
- **Доп. фильтр** — один режим из списка (остаток &gt; 0, комплекты, нули, без ожидания, без кратности, неполная упаковка); по умолчанию «— нет —».
- Кнопки: **Применить** (или Enter в поле поиска), **По умолчанию**, **Обновить**, **Скопировать ссылку**, **Пересчитать кэш** (очередь `purchase_formula_cache` — заполнение `dg_formula_proposed_cache` для дефолтной выборки; журнал на `/processes.html`).

При сортировке по **«Предлагаемый нес.ост.»** или колонкам **d_*** показывается подсказка: порядок по кэшу формулы; при пустом кэше — запустите пересчёт или дождитесь автосинхронизации (**Настройки → Автосинхронизация → Закупки: кэш формулы и окон**).

Фильтры **не запускают** сетевой запрос на каждый ввод символа — серверный fetch только по «Применить», Enter или Esc (по правилу `datagon-table-filter-apply.mdc`).

В шапке карточки таблицы есть **зеркало** поля «Умный поиск» — Enter / Esc работают так же.

Шестерёнка ⚙ слева от «Свернуть» в шапке карточки фильтров — управление видимостью полей фильтров (сохраняется в браузере для текущего пользователя).

## Управление столбцами таблицы

В шапке карточки таблицы:

- **🧩 Столбцы** — какие колонки показывать (видимость, чекбоксы);
- **📏 Ширины** — ручная ширина каждой колонки в пикселях, рядом — drag за правый край заголовка;
- **Свернуть** — сворачивает только тело карточки таблицы.

Выбор столбцов и ширины сохраняется в `localStorage` для каждого пользователя.

## REST API

Полное описание — в [REST API](/docs/api/#закупки):

- `GET /api/purchase` — список товаров с overrides (фильтры, пагинация, сортировка). **Расхождение НС** (`ms_formula_diff=1`) — отдельный селект в «Фильтры и действия»: только позиции, где неснижаемый МС ≠ предлагаемый по формуле. Доп. режимы (селект «Доп. фильтр»): **нулевой остаток** (`zero_stock`), **нулевой без ожидания** (`zero_stock_no_transit`), **без кратности** (`no_multiplicity`), **неполная упаковка** (`incomplete_pack`), **только с остатком** (`only_stock`), **комплекты** (`include_bundles`), **к закупке** (`to_purchase`).
- `POST /api/purchase/override` — сохранить одно значение (`code` + `field` + `value`).
- `POST /api/purchase/overrides-import` — пакетный импорт CSV для **Нес.остаток Датагон**, **Кратность товара**, **Мин. остаток сч.как 0** (только HTTP; на `/purchase.html` кнопок импорта нет — см. [REST API — Закупки](/docs/api#закупки), подзаголовок `POST /api/purchase/overrides-import`).

Сортировка по **`formula_proposed_min_stock`**, **`in_transit`** и колонкам **`d_*`** (`sort_by=…`): порядок считается **по всему отфильтрованному списку**, затем к ответу применяются `limit`/`offset` (см. [REST API — GET `/api/purchase`](/docs/api/#get-apipurchase)). Для **`formula_proposed_min_stock`** на полном наборе используется **двухфазный** расчёт (без чтения `payload_json` и без агрегатов окон **3…365** на всех строках — только формула), затем для **текущей страницы** — полные данные с payload и колонками **`d_*`**, как при обычном списке. По **`in_transit`** и **`d_*`** тяжёлые агрегаты по-прежнему по полному набору для порядка; **`formula_proposed_min_stock`** в ответе для этих режимов — только для страницы после второго enrich.

## Доступ

Раздел зарегистрирован в `lib/datagonPageRegistry.js` (`pageKey: 'purchase'`). Видимость пункта меню «Закупки товары» и доступ к API контролируются матрицей специальностей в **Настройках** (`/settings.html` → «Доступ по специальностям»):

- `hidden` — пункт меню скрыт, HTML/API закрыты;
- `view` — только просмотр (GET), сохранение overrides отключено (POST вернёт 403);
- `full` — полный доступ.

## Типичные вопросы

**Не вижу значение «Кол-во в упаковке».** В МС у товара должны быть заведены **packagings** (Упаковки). Если в карточке МС их нет, показывается прочерк / пусто; при необходимости в БД можно положить ручное значение через `pack_qty_manual` (передать в `POST /api/purchase/override`).

**Колонка «Ожидание» показывает прочерк.** Число берётся из **`inTransit`** в `ms_entity_details.payload_json`. При **полном синхронизации МойСклад** Datagon подмешивает `inTransit` и `reserve` из ответа **`report/stock/all`** в сохраняемую карточку (в самом `entity/product` с текущим expand эти поля часто не приходят). После обновления кода нужен **один успешный полный синк**; если в отчёте МС для позиции нет ожидания — останется «—».

**Сохранил Нес.остаток Датагон, но при перезагрузке его нет.** Проверьте: ячейка стала зелёной после изменения? Если да — открыть `dg_purchase_overrides` в БД и убедиться, что значение лежит. Если красная — наведите курсор на ячейку, там подсказка с текстом ошибки.
