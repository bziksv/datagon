Страница **`/product-analysis.html`** — анализ складских SKU: продажи, остатки, пресеты (мёртвые / зависшие / топы), сценарий «что делать» и запись неснижаемого в Datagon. Карта: [Карта панели](/docs/panel-map/). API: `/api/product-analysis` → `routes/productAnalysis.js` — [REST API → Анализ товаров](/docs/api/#анализ-товаров).

## Доступ

Ключ матрицы — **`product-analysis`**.

| Режим | Что доступно |
|-------|----------------|
| **`hidden`** | HTML и API недоступны |
| **`view`** | overview / ranking / export / log / comments GET; `POST/PATCH/DELETE` решений и комментариев — нет |
| **`full`** | Сценарий по SKU, комментарии, обнуление НС в Datagon, фиксация предлагаемого |

Не путать с [Анализом поставщиков](/docs/supplier-analysis/) (агрегат по поставщику) и с [Закупками](/docs/purchase/) (формула / Пр.→НС).

## Источники и таблицы

- **Каталог** — складские SKU (`sqlProductAnalysisCatalogWhere`): не архив, складская «Да», не комплект; **включая** «перестали сотрудничать» (остаток ещё может лежать).
- **Продажи** — те же join'ы, что у анализа поставщиков (`ms_demand`), агрегат **по `code`**.
- **Сценарий** — `dg_product_analysis_playbook`: какой из четырёх путей выбран, текущий шаг, дата проверки, «годен до».
- **Флаги закупки** — `dg_product_analysis_decisions`: `do_not_order`, `lock_proposed_min_stock`. Старт «Никогда не продавался» и шаг «Остановить закупки» ставят их сами. Старый список lifecycle на экране скрыт.
- **Комментарии** — `dg_product_analysis_comments` (несколько на код; правка/удаление только своих).
- **Журнал полей** — `dg_product_analysis_decisions_log` (`source`: `row`|`bulk`|`min_stock`|…).

## Как пользоваться

1. **Фильтры** (черновик → **Применить** / Enter; dirty → «Применить •»). После apply / пресета / сортировки / страницы адрес обновляется (`history.replaceState`) — ссылку можно шарить.
   Параметры URL: `days`, `new_stock_days`, `exclude_new_on_stock`, `search`, `supplier`, `manager`, `preset`, `project_mode`, `project_uuids`, `limit`, `page`, `sort_by`, `sort_dir`, `playbook`, `expiry_goods`, `review`. Старый `playbook=due` открывается как `review=due`.
2. Пресеты (чипы): `all`, `top_revenue`, `top_qty`, `dead`, `stuck`, `new_on_stock`, `dead_min_stock`, `min_vs_proposed`, `do_not_order`. Чипы lifecycle скрыты.
   - **Мёртвые** (`dead`) — 0 продаж и `stock > 0`.
   - **Зависшие** (`stuck`) — шире: остаток и (0 продаж **или** ≥30 дн. без продаж).
   - **Новые на складе** — первый положительный снимок в пределах `new_stock_days`.
   - По умолчанию `exclude_new_on_stock=1` — новинки исключаются из мёртвых/зависших/`dead_min_stock`.
   - **Решение** — чипы: все, нет сценария, были продажи, не продавался, медленно, срок. Клик сразу фильтрует список.
   - **Товар со сроком годности** — все / со сроком / без срока / авто (в «Автоматизация цены» есть «расходка» и галочку не снимали).
   - **Дата проверки** — все, уже наступила, сегодня, 3 / 7 / 14 / 30 дней. Окна «N дней» включают уже наступившие даты. Сочетается с фильтром решения.
3. Проекты отгрузок и менеджер (`ms_export.manager`) — как у supplier-analysis / закупок.
4. Карточка таблицы: зеркало поиска, **🧩 Столбцы** / **📏 Ширины** / **Свернуть**, пагинация (default **100**), раскрытие строки (`/sku-detail`).
5. Колонка **Товар со сроком годности** — галочка. Если в `ms_export.automation_price` есть слово «расходка», галочка стоит сама и помечена «авто»; её можно снять (тогда больше не вернётся, пока не поставят вручную). Ручная галочка без «расходки» тоже сохраняется. Снятие и постановка пишутся в журнал.
6. Колонка **Решение** — плашка. Серая «Нет сценария», синяя «шаг и дата», красная «Пора проверить» с датой, когда день контроля наступил. Вся строка такого товара тоже краснеет. Клик открывает модалку: четыре карточки, одна подсвечена «Похоже на это». Дальше виден только текущий шаг и кнопка «Готово, дальше». Дата проверки ставится сама (+14 или +30 дней). Пока дата впереди, шаг ждёт; в день даты плашка становится красной «Пора проверить».
6. **Массовые действия**, которые остались: фиксация предлагаемого и **обнулить неснижаемый**. Кнопки буст / распродажа / вывод / топ / держать скрыты.
   - Preflight `dry_run=1` → цифры в `#dg-pa-action-log`.
   - Confirm — **`#dg-pa-bulk-confirm-overlay`** (не `window.confirm`); без галочек — обязательный чекбокс «понимаю».
   - Итог в action-log: updated / errors / duration; история — кнопка «лог» у решения.
   - **Обнулить неснижаемый** пишет `ms_export.min_stock` **только в Datagon**; в МС — автосинк `min_stock_export` (Настройки).
7. Комментарии — модалки `#dg-pa-cmt-overlay` / `#dg-pa-cmt-del-overlay`.
