# Карточка товара (`/product.html?code=XXX`)

Детальная страница одного товара. Открывается в **новом окне** из таблицы «Закупки» (клик по столбцу «Код»). Цель — собрать в одном месте всё, что Datagon знает о товаре, без переходов между разделами.

## Источник данных

| Блок | Источник |
|------|----------|
| Основные данные | `ms_export` (синк МС) |
| Атрибуты МС | `ms_entity_details.payload_json.attributes` |
| Цены | `ms_entity_details.payload_json.{buyPrice, minPrice, salePrices[]}` (+ `ms_export.buy_price` как fallback) |
| Остатки и ожидания | `ms_export.stock`, `ms_export.min_stock`, payload `reserve` / `inTransit` (в закупках колонка «Ожидание» = `inTransit` из того же payload) |
| Override-поля «Закупки» | `dg_purchase_overrides` (создаётся в `routes/purchase.js`, заполняется на `/purchase.html`) |
| Отсутствие на складе (лог по дням) | `dg_product_zero_stock_log` — в основном автоматически после синка МС (`routes/product.js`) |
| Сводка дней без товара по окнам (Excel) | `dg_product_zero_stock_window_import` — отдельно от построчного лога |
| Продажи товара | `ms_demand` + `ms_demand_position` (привязка по `p.ms_export_code = code`) |
| Формула продаж | `lib/datagonSalesFormula.js` + глобальные ключи `app_settings.sales_formula_*` (период продаж в календарных днях — в настройках «Окно продаж»; дни без остатка из `dg_product_zero_stock_log`) |

## Структура страницы

У каждой основной карточки ниже (п.2–8) в шапке справа — кнопка **Свернуть / Развернуть** для тела карточки (`card-body`); подписи и действия, вынесенные в шапку (дата синхронизации, селект глубины лога, ссылка в «Продажи МС» и т.п.), остаются видны. Состояние запоминается в `localStorage` (ключи `datagon_product_*_card_collapsed_v1`).

1. **Шапка:** Код, Артикул, Наименование (с бейджем «Архив» если применимо), кнопка «Открыть в МойСклад» (если в payload есть `meta.uuidHref`).
2. **Данные из МойСклад** — все базовые поля `ms_export` (тип, поставщик, менеджер, НДС, упаковки, штрихкоды, изображения, описание).
3. **Атрибуты МС** — полный список атрибутов товара из payload (имя/значение/тип). Если payload пуст — подсказка обновить синк.
4. **Цены из МойСклад** — карточки на каждую цену (`buy`, `min`, все `salePrices`). Если ничего не нашли — fallback на `ms_export.buy_price`.
5. **Остатки и ожидания** — `Остаток`, `Резерв`, `В пути`, `Неснижаемый остаток (МС)`. Под ними — текущие override-поля «Закупки» (только просмотр; редактирование на `/purchase.html`).
6. **Отсутствие на складе** — по смыслу как продажи: в лог попадают только **факты из выгрузки МС**. После каждого **успешного синка** за **текущие сутки** автоматически создаётся строка, если складская позиция «Да», товар не в архиве и остаток ≤ 0 (`source=moysklad_sync`). Селект «дней» задаёт глубину **построчного лога**; над таблицей — краткая сводка (число записей и число разных календарных дней без товара). Опционально — **«Записать вручную за сегодня»** (агрегат «все склады»; автоматическая строка за этот день не перезаписывается). **Сводка по окнам из Excel** — карточки 30…365 дн. «дней без товара» до даты среза, отдельное хранилище; загрузка `POST /api/product/zero-stock-windows-import`.
7. **Продажи товара** — фиксированные агрегаты по 9 окнам; **период для графиков** задаётся датами «с / по» (или пресеты 30…730 дн.), запрос `sales_from`+`sales_to`; сохраняется в `localStorage`. Сводка «прямые vs комплекты» и таблица **«Последние отгрузки»** только из **проведённых** отгрузок (`applicable`), в одной логике с графиками. Детализация комплектов — ниже сводки. У **«Последних отгрузок»** — **пагинация** (размер страницы 50/100/200, кнопки «Назад»/«Вперёд»), фильтр **«Через»** (колонка таблицы: все / прямая продажа / только через комплект; query `recent_via`) и при последнем варианте — поле **«Код комплекта или товара»** с подсказками (`datalist`) и свободным вводом: пусто — все комплекты, иначе фильтр по `recent_bundle_code` (код строки отгрузки МС); под таблицей строка **«Найдено: N; страница X/Y; показано: K»**. Обновление без полной перезагрузки карточки — `GET /api/product/:code/recent-shipments` с теми же параметрами периода.
8. **Формула продаж** — расчёт **предлагаемого неснижаемого** для Датагон по продажам за скользящий **период** (календарные дни; в настройках параметр «Окно продаж»), коэффициенту пополнения, логу «нулевых» дат, опционально режиму экономии и порогу для «дорогих» товаров (цена с подстрокой «маркет» в названии типа цены МС). Параметры — в **Настройки** → «Формула продаж / закупки». На карточке: крупный итог и **«Формула этапами»** (`formula.detail.equation_stages`). Промежуточные числа — в **`formula.inputs`**. Подробнее — в [API](api#карточка-товара) (`GET /api/product/:code` → `formula`).

## Отсутствие товара на складе (лог)

> «Как в продажах считаются только проведённые отгрузки, так и здесь — только то, что видно в выгрузке МС в день синка.»

- После **полного синка МС** (`ms_export` перезаписан) сервер одним запросом обновляет `dg_product_zero_stock_log` за **сегодня** для всех кодов, где `stock_position='Да'`, `is_archived=0`, `stock≤0` (`source=moysklad_sync`). Ручная запись за тот же день автоматикой **не** перезаписывается.
- **«Записать вручную за сегодня»** (`POST /api/product/:code/zero-stock-log`) — добавить или обновить запись за **сегодня** с `store_uuid='__total__'` (агрегат по товару). Идемпотентно (UNIQUE по `(code, store_uuid, ts_date)`).
- Без `force=1` запись **отвергается**, если `ms_export.stock > 0` (защита от расхождения с актуальным остатком).
- Селект «дней» задаёт глубину отображаемого лога при запросе.
- **Импорт сводки из Excel** (колонка кода + пять окон 30…365 дней) не восстанавливает конкретные календарные дни и **не пишет** в `dg_product_zero_stock_log` — данные кладутся в `dg_product_zero_stock_window_import`. Повторный импорт с тем же `reference_date` и кодом перезаписывает числа для этого среза.
- **По-складская разбивка** в логе — после расширения синка `report/stock/bystore` (в схеме уже есть `store_uuid`, `store_name`).

## API

См. подробнее [Карточка товара в API](api#карточка-товара):

- `GET /api/product/:code` — агрегатный ответ для всей страницы (в т.ч. первая страница «Последних отгрузок» и мета пагинации; поле `zero_stock_windows_import` — последний импорт сводки по окнам для кода или `null`).
- `GET /api/product/:code/recent-shipments` — только список отгрузок с пагинацией и фильтром по комплекту (описание в `docs-docusaurus/docs/api.md`, подзаголовок **GET `/api/product/:code/recent-shipments`** в разделе «Карточка товара»).
- `GET /api/product/:code/zero-stock-log` — отдельная точка для перерисовки таблицы лога.
- `POST /api/product/:code/zero-stock-log` — опциональная ручная запись за сегодня.
- `POST /api/product/zero-stock-windows-import` — пакетный импорт сводки по окнам (JSON `rows` или `csv` + обязательный `reference_date`); см. раздел **POST `/api/product/zero-stock-windows-import`** в `api.md`.

## Доступ

Карточка товара использует тот же `pageKey`, что и «Закупки» (`pageKey: 'purchase'`):

- HTML `/product.html` доступен, если у пользователя `purchase` ≥ `view`.
- API `/api/product/*` тоже мапится на `pageKey: 'purchase'` (см. `lib/datagonPageRegistry.js`).
- POST `/api/product/:code/zero-stock-log` и POST `/api/product/zero-stock-windows-import` требуют уровень **`full`** для страницы «Закупки» (в режиме «только просмотр» изменяющие методы запрещены), как и POST `/api/purchase/override`.

## Открытие из таблицы «Закупки»

Столбец «Код» в `/purchase.html` отрисовывается ссылкой `<a target="_blank" rel="noopener" href="/product.html?code=XXX">`. Это единственная точка входа сейчас; при необходимости добавим открытие карточки из «МойСклад» / «Мои товары» / «Сопоставление» по запросу.
