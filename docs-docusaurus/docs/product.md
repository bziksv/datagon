# Карточка товара (`/product.html?code=XXX`)

Детальная страница одного товара. Открывается в **новом окне** из таблицы «Закупки» (клик по столбцу «Код»). Цель — собрать в одном месте всё, что Datagon знает о товаре, без переходов между разделами.

## Источник данных

| Блок | Источник |
|------|----------|
| Основные данные | `ms_export` (синк МС) + `ms.uom` из `payload_json.uom` (при meta без `name` — разрешение по href через API МС) |
| Атрибуты МС | `ms_entity_details.payload_json.attributes` |
| Цены | `ms_entity_details.payload_json.{buyPrice, minPrice, salePrices[]}` (+ `ms_export.buy_price` как fallback) |
| Остатки и ожидания | `ms_export.stock`, `ms_export.min_stock`, payload `reserve` / `inTransit` (в закупках колонка «Ожидание» = `inTransit` из того же payload) |
| История остатка по дням (после синка МС) | `dg_product_stock_snapshot` — один снимок `stock` из `ms_export` на календарную дату успешного синка; срок хранения — `app_settings.product_stock_snapshot_retention_days` (по умолчанию 365 дн.). API: `GET /api/product/:code` → `stock_snapshots` |
| Override-поля «Закупки» | `dg_purchase_overrides` (создаётся в `routes/purchase.js`, заполняется на `/purchase.html`) |
| Отсутствие на складе (лог по дням) | `dg_product_zero_stock_log` — в основном автоматически после синка МС (`routes/product.js`) |
| Сводка дней без товара по окнам на карточке | Считается из `dg_product_zero_stock_log` (`GET /api/product/:code` → `zero_stock_windows_from_log`) |
| Сводка по окнам из Excel (пакетно) | `dg_product_zero_stock_window_import` — для закупок и слияния с логом в формуле (`mergeAbsenceDistinctForFormula`), не подменяет построчный лог |
| Продажи товара | `ms_demand` + `ms_demand_position` (привязка по `p.ms_export_code = code`) |
| Формула продаж | `lib/datagonSalesFormula.js` + `app_settings.sales_formula_*`; дни без остатка за A — **max** построчного лога `dg_product_zero_stock_log` и оценки по последнему импорту сводки `dg_product_zero_stock_window_import` (см. `lib/datagonZeroStockAbsence.js`), не выше A |

## Структура страницы

У каждой основной карточки ниже (п.2–8) в шапке справа — кнопка **Свернуть / Развернуть** для тела карточки (`card-body`); подписи и действия, вынесенные в шапку (дата синхронизации, селект глубины лога, ссылка в «Продажи МС» и т.п.), остаются видны. Состояние запоминается в `localStorage` (ключи `datagon_product_*_card_collapsed_v1`).

1. **Шапка:** Код, Артикул, Наименование (с бейджем «Архив» если применимо), кнопка «Открыть в МойСклад» (если в payload есть `meta.uuidHref`).
2. **Данные из МойСклад** — все базовые поля `ms_export` (тип, поставщик, менеджер, НДС, упаковки, штрихкоды, изображения, описание).
3. **Атрибуты МС** — полный список атрибутов товара из payload (имя/значение/тип). Если payload пуст — подсказка обновить синк.
4. **Цены из МойСклад** — карточки на каждую цену (`buy`, `min`, все `salePrices`). Если ничего не нашли — fallback на `ms_export.buy_price`.
5. **Остатки и ожидания** — `Остаток`, `Резерв`, `В пути`, `Неснижаемый остаток (МС)`, при наличии формулы — **предлагаемый неснижаемый (Датагон)**. Ниже — таблица **истории остатка по дням** (селект «Период» и снимки после синков МС; глубина не больше min(730, срок хранения из настроек)). Далее — форма **трёх полей закупок** (неснижаемый Датагон, кратность, мин. остаток «считать как 0»): сохранение через `POST /api/purchase/override`, если в ответе `GET /api/product/:code` поле **`purchase_overrides_editable`** равно `true` (полный доступ к разделу «Закупки» в матрице прав; при `view` поля только для чтения). Поле **«Неснижаемый остаток Датагон»** (`min_stock_dg`) **не** задаёт опорный baseline для шагов формулы; если там задано значение **> 0**, показанный предлагаемый неснижаемый **не ниже** него. Остальные override (предлагаемый нес.ост. из закупок, упаковка, заметка) — блоком ниже.
6. **Отсутствие на складе** — по смыслу как продажи: в лог попадают только **факты из выгрузки МС**. После каждого **успешного синка** за **текущие сутки** автоматически создаётся строка, если складская позиция «Да», товар не в архиве и остаток ≤ 0 (`source=moysklad_sync`). Селект «дней» задаёт глубину **построчного лога**; над таблицей — краткая сводка (число записей и число разных календарных дней без товара). **Сводка по окнам 30…365** на той же странице считается **из этого лога** (разные даты в скользящих окнах до сегодня по серверу). Опционально — **«Записать вручную за сегодня»** (агрегат «все склады»; автоматическая строка за этот день не перезаписывается). Пакетный **импорт Excel** (`POST /api/product/zero-stock-windows-import`) — для массовой истории и формулы закупок, **не** источник цифр в блоке сводки на карточке.
7. **Продажи товара** — фиксированные агрегаты по 9 окнам; **период для графиков** задаётся датами «с / по» (или пресеты 30…730 дн.), запрос `sales_from`+`sales_to`; сохраняется в `localStorage`. Сводка «прямые vs комплекты» и таблица **«Последние отгрузки»** только из **проведённых** отгрузок (`applicable`), в одной логике с графиками. Детализация комплектов — ниже сводки. У **«Последних отгрузок»** — **пагинация** (размер страницы 50/100/200, кнопки «Назад»/«Вперёд»), фильтр **«Через»** (колонка таблицы: все / прямая продажа / только через комплект; query `recent_via`) и при последнем варианте — поле **«Код комплекта или товара»** с подсказками (`datalist`) и свободным вводом: пусто — все комплекты, иначе фильтр по `recent_bundle_code` (код строки отгрузки МС); под таблицей строка **«Найдено: N; страница X/Y; показано: K»**. Обновление без полной перезагрузки карточки — `GET /api/product/:code/recent-shipments` с теми же параметрами периода.
8. **Формула продаж** — расчёт **предлагаемого неснижаемого** (`lib/datagonSalesFormula.js`, **v2**): средний спрос за **W** дн. («Продажи за период»); оценка «упущенных» = число дней отсутствия за **A** дн. (max по логу нулей и импорту окон, см. `lib/datagonZeroStockAbsence.js`) × этот средний спрос; **сумма с учётом отсутствий** = продажи за W + упущенные; если товар **не дорогой** (цена «маркет» ≤ порога) и **сумма продаж за W ≤ 1 шт** (без «упущенных») — итог = **«Базовый запас для товаров с редкими продажами»** (`sales_formula_rare_base_qty`, с ограничением скачка; **в формуле не ниже 1 шт**, даже если в настройках 0) и **не ниже кратности из закупок**, если в закупках задана кратность ≥ 1 шт; иначе черновик **(сумма × k)** без прибавки **«Базовый запас»** и **«Базовый запас для дорогих…»** к произведению; затем **кратность** из закупок и **«Процент от упаковки»**: при ненулевом пороге доля хвоста **≤** порога — округление **вниз** до кратности; **строго больше** порога — **вверх**; при сигнале спроса итог **не ниже** кратности из закупок; затем **«Макс. изменение»** только на повышение; затем минимум по классификации (**«Базовый запас»** / **«Базовый для дорогих…»**); при нуле после кратности при ненулевой сумме с учётом отсутствий — подстановка редкого/дорогого минимума; при дроби &lt; 1 шт — `sales_formula_rare_base_qty` / `sales_formula_expensive_rare_min_qty`. Параметры — **Настройки** → «Формула продаж / закупки». Подробнее — [API](api#карточка-товара).

## Отсутствие товара на складе (лог)

> «Как в продажах считаются только проведённые отгрузки, так и здесь — только то, что видно в выгрузке МС в день синка.»

- После **полного синка МС** (`ms_export` перезаписан) сервер одним запросом обновляет `dg_product_zero_stock_log` за **сегодня** для всех кодов, где `stock_position='Да'`, `is_archived=0`, и выполняется **остаток ≤ 0** или (только для кода **без** «-» в номенклатуре) **остаток &lt; минимального числового суффикса** среди строк `ms_export` с кодом вида `<тот же код>-<целое>` (например при `27877-2` и `27877-10` порог для `27877` = 2 шт.) (`source=moysklad_sync`). Ручная запись за тот же день автоматикой **не** перезаписывается.
- **«Записать вручную за сегодня»** (`POST /api/product/:code/zero-stock-log`) — добавить или обновить запись за **сегодня** с `store_uuid='__total__'` (агрегат по товару). Идемпотентно (UNIQUE по `(code, store_uuid, ts_date)`).
- Без `force=1` запись **отвергается**, если `ms_export.stock > 0` (защита от расхождения с актуальным остатком).
- Селект «дней» задаёт глубину отображаемого лога при запросе.
- **Импорт сводки из Excel** (колонка кода + пять окон 30…365 дней) не восстанавливает конкретные календарные дни и **не пишет** в `dg_product_zero_stock_log` — данные кладутся в `dg_product_zero_stock_window_import`. Повторный импорт с тем же `reference_date` и кодом перезаписывает числа для этого среза.
- **По-складская разбивка** в логе — после расширения синка `report/stock/bystore` (в схеме уже есть `store_uuid`, `store_name`).
- **История остатка по дням** — таблица `dg_product_stock_snapshot`: после каждого **успешного полного синка** МС пишется одно значение `ms_export.stock` на **`CURDATE()`** для каждого кода (повторный синк в тот же день обновляет число). Срок хранения в БД — **`product_stock_snapshot_retention_days`** в [Настройках](/settings.html) (по умолчанию **365** дней, 30…3650). Глубину таблицы на карточке задаёт селект «Период» (не больше **min(730, срок хранения)**; query `stock_snapshot_days` у `GET /api/product/:code`; в ответе не более 400 строк). Это **не** замена логу отсутствий: там фиксируются дни, когда выполнялись условия «нет на складе», здесь — сырое число остатка из выгрузки.

## API

См. подробнее [Карточка товара в API](api#карточка-товара):

- `GET /api/product/:code` — агрегатный ответ для всей страницы (в т.ч. первая страница «Последних отгрузок» и мета пагинации; поле `zero_stock_windows_from_log` — расчёт окон 30…365 из лога; `zero_stock_windows_import` — последний пакетный импорт Excel по коду или `null`; **`stock_snapshots`** — снимки `ms_export.stock` по дням из `dg_product_stock_snapshot`).
- `GET /api/product/:code/recent-shipments` — только список отгрузок с пагинацией и фильтром по комплекту (описание в `docs-docusaurus/docs/api.md`, подзаголовок **GET `/api/product/:code/recent-shipments`** в разделе «Карточка товара»).
- `GET /api/product/:code/zero-stock-log` — отдельная точка для перерисовки таблицы лога.
- `POST /api/product/:code/zero-stock-log` — опциональная ручная запись за сегодня.
- `POST /api/product/zero-stock-windows-import` — пакетный импорт сводки по окнам (JSON `rows` или `csv` + обязательный `reference_date`); см. раздел **POST `/api/product/zero-stock-windows-import`** в `api.md`.

## Доступ

Карточка товара использует тот же `pageKey`, что и «Закупки» (`pageKey: 'purchase'`):

- HTML `/product.html` доступен, если у пользователя `purchase` ≥ `view`.
- API `/api/product/*` тоже мапится на `pageKey: 'purchase'` (см. `lib/datagonPageRegistry.js`).
- POST `/api/product/:code/zero-stock-log` и POST `/api/product/zero-stock-windows-import` требуют уровень **`full`** для страницы «Закупки» (в режиме «только просмотр» изменяющие методы запрещены), как и POST `/api/purchase/override`.

## Открытие из таблицы «Закупки»

В колонке **«Наименование»** на `/purchase.html` выводится **код** товара ссылкой `<a target="_blank" rel="noopener" href="/product.html?code=XXX">` (и кнопка **🕘 Лог** журнала закупок по коду). Это основная точка входа в карточку из закупок; при необходимости добавим открытие из «МойСклад» / «Мои товары» / «Сопоставление» по запросу.
