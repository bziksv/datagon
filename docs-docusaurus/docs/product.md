# Карточка товара (`/product.html?code=XXX`)

Детальная страница одного товара. Открывается в **новом окне** из таблицы «Закупки» (клик по столбцу «Код»). Цель — собрать в одном месте всё, что Datagon знает о товаре, без переходов между разделами.

## Источник данных

| Блок | Источник |
|------|----------|
| Основные данные | `ms_export` (синк МС) |
| Атрибуты МС | `ms_entity_details.payload_json.attributes` |
| Цены | `ms_entity_details.payload_json.{buyPrice, minPrice, salePrices[]}` (+ `ms_export.buy_price` как fallback) |
| Остатки и ожидания | `ms_export.stock`, `ms_export.min_stock`, payload `reserve` / `inTransit` |
| Override-поля «Закупки» | `dg_purchase_overrides` (создаётся в `routes/purchase.js`, заполняется на `/purchase.html`) |
| Нулевые остатки по складам | `dg_product_zero_stock_log` (создаётся в `routes/product.js`) |
| Сводка «нулей» по окнам (импорт Excel) | `dg_product_zero_stock_window_import` — отдельно от построчного лога |
| Продажи товара | `ms_demand` + `ms_demand_position` (привязка по `p.ms_export_code = code`) |
| Формула продаж | TBD (заглушка, см. ниже) |

## Структура страницы

1. **Шапка:** Код, Артикул, Наименование (с бейджем «Архив» если применимо), кнопка «Открыть в МойСклад» (если в payload есть `meta.uuidHref`).
2. **Данные из МойСклад** — все базовые поля `ms_export` (тип, поставщик, менеджер, НДС, упаковки, штрихкоды, изображения, описание).
3. **Атрибуты МС** — полный список атрибутов товара из payload (имя/значение/тип). Если payload пуст — подсказка обновить синк.
4. **Цены из МойСклад** — карточки на каждую цену (`buy`, `min`, все `salePrices`). Если ничего не нашли — fallback на `ms_export.buy_price`.
5. **Остатки и ожидания** — `Остаток`, `Резерв`, `В пути`, `Неснижаемый остаток (МС)`. Под ними — текущие override-поля «Закупки» (только просмотр; редактирование на `/purchase.html`).
6. **Нулевые остатки по складам** — таблица истории (конкретные даты) + кнопка «Зафиксировать нулевой остаток сейчас» и селект периода. **Сводка по окнам** (30 / 60 / 90 / 180 / 365 дней «отсутствия», как в историческом Excel) показывается отдельным блоком, если для кода есть импорт в `dg_product_zero_stock_window_import` (загрузка через `POST /api/product/zero-stock-windows-import` или скрипт в репозитории). Пакетно за **сегодня** при **успешном синке МойСклад** в `ms_export` сервер пишет строки с `source=moysklad_sync` только для позиций **складская позиция = Да**, **не архив**, **остаток ≤ 0** (один SQL-upsert; ручная запись за тот же день не затирается).
7. **Продажи товара** — фиксированные агрегаты по 9 окнам; **период для графиков** задаётся датами «с / по» (или пресеты 30…730 дн.), запрос `sales_from`+`sales_to`; сохраняется в `localStorage`. Сводка «прямые vs комплекты» и таблица **«Последние отгрузки»** только из **проведённых** отгрузок (`applicable`), в одной логике с графиками. Детализация комплектов — ниже сводки. У **«Последних отгрузок»** — **пагинация** (размер страницы 50/100/200, кнопки «Назад»/«Вперёд»), фильтр **«Через»** (колонка таблицы: все / прямая продажа / только через комплект; query `recent_via`) и при последнем варианте — **«Код комплекта»** («все комплекты» или конкретный код); под таблицей строка **«Найдено: N; страница X/Y; показано: K»**. Обновление без полной перезагрузки карточки — `GET /api/product/:code/recent-shipments` с теми же параметрами периода.
8. **Формула продаж** — заглушка. Конкретные коэффициенты предоставит пользователь отдельно. Заготовлено место для компонент: средние продажи по окнам, доля «нулевых» дней, кратность, нес.остаток Датагон.

## Фиксация «нулевых остатков»

> «Когда товара нет на складе в этот день — мы записываем его отсутствие.»

- После **полного синка МС** (`ms_export` перезаписан) сервер одним запросом обновляет `dg_product_zero_stock_log` за **сегодня** для всех кодов, где `stock_position='Да'`, `is_archived=0`, `stock≤0` (`source=moysklad_sync`). Ручная запись за тот же день не меняется.
- Кнопка **«Зафиксировать нулевой остаток сейчас»** добавляет/обновляет запись за **сегодня** с `store_uuid='__total__'` (общая фиксация по товару). Идемпотентно (UNIQUE по `(code, store_uuid, ts_date)`).
- Без `force=1` фиксация **отвергается**, если `ms_export.stock > 0` (защита от ложных записей при актуальных остатках).
- Селект «дней» определяет глубину отображаемого лога (не записи).
- **Импорт сводки из Excel** (колонка кода + пять окон 30…365 дней) не восстанавливает конкретные календарные дни и **не пишет** в `dg_product_zero_stock_log` — данные кладутся в `dg_product_zero_stock_window_import` и на карточке показываются рядом с логом. Повторный импорт с тем же `reference_date` и кодом перезаписывает числа для этого среза.
- **По-складская разбивка** (отдельная строка на каждый магазин/склад) появится после расширения синка `report/stock/bystore` — в схеме место уже зарезервировано (`store_uuid`, `store_name`).

## API

См. подробнее [Карточка товара в API](api#карточка-товара):

- `GET /api/product/:code` — агрегатный ответ для всей страницы (в т.ч. первая страница «Последних отгрузок» и мета пагинации; поле `zero_stock_windows_import` — последний импорт сводки по окнам для кода или `null`).
- `GET /api/product/:code/recent-shipments` — только список отгрузок с пагинацией и фильтром по комплекту (описание в `docs-docusaurus/docs/api.md`, подзаголовок **GET `/api/product/:code/recent-shipments`** в разделе «Карточка товара»).
- `GET /api/product/:code/zero-stock-log` — отдельная точка для перерисовки таблицы лога.
- `POST /api/product/:code/zero-stock-log` — ручная фиксация.
- `POST /api/product/zero-stock-windows-import` — пакетный импорт сводки по окнам (JSON `rows` или `csv` + обязательный `reference_date`); см. раздел **POST `/api/product/zero-stock-windows-import`** в `api.md`.

## Доступ

Карточка товара использует тот же `pageKey`, что и «Закупки» (`pageKey: 'purchase'`):

- HTML `/product.html` доступен, если у пользователя `purchase` ≥ `view`.
- API `/api/product/*` тоже мапится на `pageKey: 'purchase'` (см. `lib/datagonPageRegistry.js`).
- POST `/api/product/:code/zero-stock-log` и POST `/api/product/zero-stock-windows-import` требуют уровень **`full`** для страницы «Закупки» (в режиме «только просмотр» изменяющие методы запрещены), как и POST `/api/purchase/override`.

## Открытие из таблицы «Закупки»

Столбец «Код» в `/purchase.html` отрисовывается ссылкой `<a target="_blank" rel="noopener" href="/product.html?code=XXX">`. Это единственная точка входа сейчас; при необходимости добавим открытие карточки из «МойСклад» / «Мои товары» / «Сопоставление» по запросу.
