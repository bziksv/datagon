Модуль учёта рабочего времени, отпусков и начислений. Таблицы `ws_*`, API `/api/work-schedule/*` → `routes/workSchedule.js`. Карта: [Карта панели](/docs/panel-map/).

| HTML | Ключ матрицы |
|------|----------------|
| `/work-schedule.html` | `work-schedule` — Мой день / Отдел / Табель (+ экспорт 1С CSV) |
| `/work-schedule-settings.html` | `work-schedule-settings` — организации, отделы, сотрудники |

Оба пункта в сайдбаре. Не путать с глобальными [Настройками](/docs/settings/) (`/settings.html`).

## Доступ

| Слой | Правило |
|------|---------|
| HTML | Отдельные ключи: скрытый `work-schedule` не открывает табель; скрытый `work-schedule-settings` не открывает настройки |
| API `/api/work-schedule/*` | Режим = **max** из двух ключей (`getApiPageModeForActor`): бухгалтерия может иметь только settings и всё равно писать в API |
| `/clock/*`, `/access` | Без page-lock в `API_PREFIX_RULES` (`null`) — любой авторизованный; карточка сотрудника проверяется в роутере |

| Роль | Как определяется | Что можно |
|------|------------------|-----------|
| Сотрудник | `ws_employee.user_id` = текущий user | clock start/stop, «Мой день», свои отпуска |
| Руководитель | `ws_department.head_user_id` = actor.id | матрица отдела, кто работает сегодня, stuck, согласование отпусков |
| Бухгалтерия | specialty «Бухгалтерия» или admin / «Полный доступ» | настройки, табель всех, payroll, ручные/продажи-премии, audit, экспорт 1С |

Кнопка часов в шапке (`DatagonWorkClock`) → `POST /clock/start|stop`, `GET /clock/status`. После «Закончить» можно снова «Старт» в тот же день (сегменты накапливаются).

## Отделы = специальности (важно)

**Источник истины для списка отделов графика — специальности** из Настроек → «Специальности и доступ к разделам» (`specialties`), **не** произвольные названия вроде «Продажи».

- На `/work-schedule-settings.html` кнопка **«Подтянуть группы»** → `POST /departments/import-specialties`: создаёт `ws_department` с теми же именами, что у специальностей (кроме «Полный доступ»), без привязки к юрлицу, без дублей имён.
- Правильный отдел продаж в графике — **«Менеджер по продажам»** (как specialty id 9), а не отдельный «Продажи».
- Отдел **«Продажи»** в `ws_department` — **лишний/устаревший** (не из списка специальностей). Если сотрудник оказался там (например Юлия Елагина) — перевести в **«Менеджер по продажам»** и удалить пустой «Продажи» в настройках графика. Ручное «Добавить» отдел с именем вне специальностей не нужно.
- Дубликаты специальностей (например два «Проект-Менеджер») тоже лучше схлопнуть в Настройках — иначе при импорте появятся два отдела с одним смыслом.

## Экраны `/work-schedule.html`

### Мой день

- Статус смены, Старт/Стоп, таймер.
- **Расчёт ЗП** за месяц: часы (ЧЧ:ММ), смены (ставки / норма), **оклад** (накапало + ставка), премия, **доплата за стаж** (накапало + полная), отпускные/больничные, итого.
- Клик по чипу оклада — история (`GET /employees/:id/salary-history`).
- Календарь месяца; клик по дню → `GET /me/day` (сегменты, IP).
- Заявка на отпуск.

### Отдел

- Матрица сотрудники × дни; в шапке колонок — **число и день недели** (пн…вс; выходные подсвечены).
- **«Кто работает сегодня»** — статус работает / закончил / не начинал (+ отпуск/больничный), время старта, часы.
- **«Открытые смены отдела»** — только сотрудники текущего отдела (`GET /stuck-shifts?department_id=`).
- Согласование отпусков.

### Табель (бухгалтерия)

- Фильтры: **умный поиск сотрудника** (ФИО / отдел; Enter или «Применить»; зеркало в шапке таблицы), организация, отдел, месяц.
- KPI: человеко-дни, ФОТ (оценка), число сотрудников.
- Таблица: ФИО | **Оклад** (накапало / ставка) | **Премия** (накапало / полная или «ручная») | дни 1…31 | Σ.
- Ячейки с открытым таймером — **светло-зелёное мигание** + «▶»; легенда «на работе (таймер)».
- Клик по дню — правка ставки/часов/типа.
- Клик по **Премии** — ручной ввод за месяц (`PATCH /sheet/premium` → `premium_manual` + `premium_source=manual`). «По правилу» снимает ручной ввод.
- **Премии из продаж** подтягиваются **сами** при `GET /sheet` для отделов с «продаж» в названии (`premium_source=sales`, сумма = `totals.bonus` как на [Таблицах менеджеров](/docs/manager-sales/)). Кнопка **«Обновить из продаж»** — принудительный пересчёт (в т.ч. поверх ручных) после новых оплат в журнале.
- Dry-run / apply payroll, экспорт CSV, журнал аудита.

## Clock и часы

- Сегменты в `ws_work_log.segments_json` (`in`/`out`/`ms`/`hours`/`ip_*`).
- `hours_worked` — сумма сегментов; в UI длительности — **ЧЧ:ММ** (не «0.77 ч»).
- Ставка дня (0 / 0,5 / 1) по порогам часов отдела/сотрудника; короткие куски не обнуляются до 5 мин для отображения часов.
- **Автозакрытие** (тик ~15 мин): смена суток МСК → `day-rollover` на `23:59:59`; иначе лимит `clock_auto_close_hours` → `auto-close`. Статус `needs_confirm`.

## Экраны `/work-schedule-settings.html`

Ключ матрицы **`work-schedule-settings`**. Обычно **`full`** у Бухгалтерии / Полный доступ; табель при этом может быть на ключе `work-schedule` или открыт через API max.

Порядок карточек:

1. **Организации** — селект «какую править» (не фильтрует сотрудников), поля: название, ИНН, TZ, больничный неофиц. ₽/день, стаж (база / шаг / период мес.). Сохранить → inline `#dg-ws-set-org-msg`. Удаление — своя модалка; **409**, если есть сотрудники. Seed при пустой таблице: **АЛЬМАМЕД** / **ВИЛМЕД**.
2. **Отделы** — общий справочник (без привязки к юрлицу). **«Подтянуть группы»** → `POST /departments/import-specialties` (имена из `specialties`, без «Полный доступ», без дублей). Карточка отдела (overlay): тип графика 5/2|2/2|сменный|гибкий, норма дня, пороги ставки 1 / 0,5, лимит отпусков, правило премии `stub` / `fixed` / `fixed_full`.
3. **Сотрудники** — фильтр орг. в шапке + умный поиск (**Применить** / Enter, не на каждый `input`). Колонки: ФИО, орг, отдел, дата приёма, **Стаж** (`N г. M мес.`), **За стаж**, оклад, личный график/норма/больничный/премия, переопределения. **Привязать пользователя** — из `GET /users-available` + обязательный `hire_date`. История оклада — `GET /employees/:id/salary-history` → `ws_audit_log` (`field_name=salary`).

Календарь праздников (`/calendar`) и маппинг 1С (`/1c-map`) — в API; экспорт CSV 1С — кнопка на **`/work-schedule.html`** (табель), не на этой странице.

## Организации и сотрудники (модель)

- Несколько юрлиц; сотрудник = `users` + орг + отдел + `hire_date`.
- Отделы = специальности (см. выше); не заводить «Продажи» вместо **«Менеджер по продажам»**.

## Начисления

| Компонент | Формула |
|-----------|---------|
| Оклад | `salary × (ставки / норма дней)`; в API: `salary_rate` + `base_salary` (накапало) |
| Стаж | полная сумма за месяц × (ставки / норма); `seniority_full` + `seniority_bonus` |
| Премия из правила | `stub` / `fixed` (пропорция) / `fixed_full` (целиком); личное правило → отдел |
| Премия ручная / из продаж | `premium_manual` + `premium_source` (`manual` / `sales`) за `period_ym` **перекрывает** правило; автозагрузка sales при открытии табеля |

Норма дней — из календаря/`monthNormDays` по типу графика отдела (5/2, 2/2, …).

## Связь с таблицами менеджеров

| Manager-sales | Work schedule |
|---------------|---------------|
| `GET /api/manager-sales` → `totals.bonus` | `GET /sheet` (auto) и `POST /sheet/premium-from-sales` (force) → `premium_manual` + `premium_source=sales` |
| credit = `COALESCE(handed_to_user_id, manager_user_id)` | сопоставление по `ws_employee.user_id` |
| % МП. от суммы F и плана | `lib/managerSalesMonthBonus.js` (та же логика) |

Специальность для доступа к журналу — **«Менеджер по продажам»**; отдел в графике должен называться так же после «Подтянуть группы».
