Страница **`/finance.html`** показывает **балансы** и **проводки** банков **Точка**, **Райффайзен** и **Т‑Банк**, плюс **наличные** (ручной ввод: разовые и ежемесячные шаблоны) и **плановые денежные операции** (бюджет по ИНН). Банковские выписки — только чтение: исходящие платежи и вебхуки не вызываются. Код валюты **`RUR`** (устаревший рубль из Райфа) нормализуется в **`RUB`** и входит в «Всего доступно», а не в «Другие валюты».

Порядок карточек на экране: **Настройки банка → Фильтры и действия → Балансы → Аналитика / Контрагенты / Движение → Наличные → Плановые денежные операции**.

## Доступ

Ключ матрицы специальностей — **`finance`**.

- **`full`** — ключи банков, «Проверить связь», «Обновить из банка», расписание автосинка, **CRUD наличных и плановых статей**.
- **`view`** — карточки остатков, таблица движения, просмотр наличных и планов; поля токенов и запись cash/plans скрыты.
- **`hidden`** — страница и `/api/finance` недоступны.

## JWT Точки (несколько организаций)

На `/finance.html` можно сохранить **несколько JWT** — по одному на организацию (или один ключ с правами на все компании).

Хранение: `app_settings.finance_tochka_credentials` (JSON-массив `{ id, label, jwt, enabled, customer_codes, customer_names }`). Старый одиночный ключ `finance_tochka_jwt` при первом чтении **мигрирует** в первую запись списка и дальше дублирует JWT первого включённого ключа (back-compat).

Колонка **«Организация»** — ручное `label` (или авто из первого ООО в клиентах JWT, без склейки «ООО · ИП»). Колонка **«Клиенты»** показывает всех `customer_names` по ключу (у одного JWT в кабинете Точки может быть несколько юрлиц).

TLS к `enter.tochka.com` — через CA Минцифры (`certs/russian-trusted-ca-bundle.pem`). **Client ID** / **Client Secret** не используются.

В общем `GET /api/settings` JWT, ключи Райфа и токен T‑API **нет** — только маски через `/api/finance/config`.

## Райффайзен (Open API)

Карточка «Настройки банка» на `/finance.html`: `client_id`, `client_secret`, `refresh_token` из RBO (**Интеграция банка с учетными системами** → API-оркестратор → «Выпустить Refresh-токен»).

Хранение: `app_settings.finance_raiffeisen_credentials`. Datagon сам обменивает refresh на `access_token` + `id_token` (`POST https://sso.rbo.raiffeisen.ru/token`) и **записывает новый refresh** (банк его ротирует).

Синк (только чтение):

1. `GET /api/v1/accounts`
2. Итоговые выписки и операции `GET /api/v1/accounts/{n}/statements` + `GET /api/v1/statement/transactions` (за текущий день — `/intraday`)
3. Счета и проводки в те же `dg_finance_accounts` / `dg_finance_tx` с `bank='raiffeisen'`

Длинное окно (например **365 дн.**) на стороне Datagon **режется на куски по 31 дню**: API Райфа при одном `from`/`to` на год часто отдаёт только хвост (~90–120 дней), из‑за чего в логе «676 проводок» при этом в БД минимум с июня. Пагинация списка выписок: параметр `limit` + продолжение, пока страница полная (если банк не прислал `totalPages`).

Банк может требовать **белый список IP** интеграции. Ошибки SSO/API видны в «Проверить Райф» и журнале синка.

Кнопка **«Загрузить выписки»** / **«Обновить все»** тянет **все три** банка (если ключи включены). У строки ключа — только этот ключ.

## Т‑Банк (T‑API)

Карточка «Настройки банка» на `/finance.html`: Bearer-токен из кабинета **Т‑Бизнес → Интеграции → T‑API → «Выпустить токен»**. В токене должен быть IP машины Datagon.

Хранение: `app_settings.finance_tbank_credentials`. Синк (только чтение): `GET /api/v1/bank-accounts` (если 404 — v2/v3) и `GET /api/v1/statement` на `https://business.tbank.ru/openapi`. Счета и проводки в `dg_finance_accounts` / `dg_finance_tx` с `bank='tbank'`. Организация в фильтрах — `tb:{inn}`.

Часть методов банка живёт на secured-openapi (mTLS). Без сертификата в журнале будет ошибка T‑API — это ограничение банка, не UI.

## Что делает синк

Кнопка **«Обновить все»** (и опционально автосинк `finance_tochka`):

1. Точка: `GET /open-banking/v1.0/accounts` (+ `customers`) → балансы → Statement
2. Райф: счета + выписки за окно дат
3. Т‑Банк: счета + выписка T‑API за окно дат
4. Экран читает **снимок из БД**

Период выписки — 1…1095 дней (~3 года; по умолчанию 30).

**Ограничение API: депозиты и фонды**

В Open Banking Точки нет отдельных endpoint’ов для фондов и часто нет балансов депозитных счетов (только `CurrentAccount`). Поэтому:

- **«На депозитах»** — оценка из выписки: сумма назначений «открытия депозита» минус «Возврат средств по депозитной сделке» (тело). Карточка всегда рядом с балансами организации (не зависит от галки «внутренние»). В **«Всего доступно»** входят расчётные счета + эта оценка. Проценты по депозиту остаются в доходе и в графике; тело депозита из графика по-прежнему исключено.
- На карточках счетов можно вручную: карандаш / клик по названию → поле имени и галка **«Фонд»** (то же, что клик по бейджу типа); задать **своё название** (`custom_name`).

Поля хранятся в `dg_finance_accounts` (`is_fund`, `custom_name`) и **не затираются** синком из банка. В фильтре «Счёт» и в таблице движения отображается custom_name, если задано.

Практика по текущему JWT: API часто отдаёт только `CurrentAccount`; нужные «фонды» в интернет-банке помечайте на карточках вручную.

**Названия организаций** (карандаш на шапке блока счетов): **полное** и **короткое** в `app_settings.finance_org_aliases`.
- **Короткое** — на карточках балансов.
- **Полное** — в фильтре «Организация», колонке «Движение», аналитике и поиске.

Таблица **«Движение»**: колонка **«Организация»** — полное имя; колонка **«Банк»** — Точка / Райффайзен / Т‑Банк / **Наличные**. Фильтр **«Источник»**: **Банк** / **Нал** / **Всё** (`source` в URL). Отдельное поле **«ИНН»** (`inn` в URL) — по ИНН контрагента (не путать с умным поиском и с галкой исключения личного ИНН из графика). Клик по строке в «Контрагентах» подставляет ИНН в это поле. Фильтр **«Организация»** — множественный (чекбоксы): разные банки по одной юрфирме — разные `customer_code`, их можно выбрать вместе. Пусто = все. Наличные со **scope = все компании** видны при любом выборе орг (трата «на группу»). **Применённые** фильтры пишутся в query URL (`customer_code`, `source`, `date_from`/`date_to`, `direction`, `account_id`, `search`, `inn`, `include_internal`, `founder_capital`, `dividend`, `page`…) — ссылку можно скопировать коллеге; лишние параметры вроде `v=` сохраняются. Операции внутреннего оборота (депозит UNV, перевод своих, дивиденды) помечены бейджем **«не в графике»** (видны при включённой галке внутренних). Колонка **«Займ / див.»** (полный доступ) — для **банка**: компактные галки **займ** и **див.** с **модалкой подтверждения**; для **наличных** — галка **в графике**. Синк выписки банковские пометки не затирает. Фильтры **«Только капитал / займ»** и **«Только дивиденды»** + «Применить» (только банк). Поиск, даты, входящие/исходящие, счёт; пагинация «Найдено / страница / показано», 100 строк по умолчанию. Галка **«Показывать депозиты, фонды и дивиденды»** (фильтры) — по умолчанию выкл.: в таблице и аналитике скрыты тело депозита UNV, «Перевод собственных средств» и **«Выплата дивидендов»**; проценты и платежи из фонда (налоги и т.п.) видны.

## Наличные

Карточка **«Наличные»** (сворачиваемая): сверху **дашборд**, ниже вкладки **Разовые** и **Ежемесячные шаблоны**.

- **Дашборд** (`GET /api/finance/cash/summary`, период/орг. из применённых фильтров): график и «чистый факт» — **только разовые** (`fact_source=once`). Авторазворот шаблонов **не** входит в столбцы «Исход/Вход» (иначе каждый месяц +фикс шаблонов). Шаблоны — отдельный KPI «за период» и виджет **прогноза на следующий месяц**.
- **Разовая** — дата, сумма, направление, назначение, **привязка** (все компании / конкретная организация), опционально **статья плана**, галка «в графике». Таблица `dg_finance_cash_tx`. После «Добавить» поля формы **не сбрасываются**. В списке — **Изменить** / **Удалить**.
- **Шаблон** — день месяца (1–28), **фикс** + опциональная **премия**, назначение, привязка, **статья плана**, «в графике по умолчанию», галка **«Требуется проверка»**. Таблица `dg_finance_cash_templates`. На чтении шаблон **разворачивается** на месяцы периода фильтра; помесячные правки — `dg_finance_cash_overrides` (фикс / премия / назначение / пропуск / в графике / `review_confirmed`). Если у шаблона «Требуется проверка», автопроводка жёлто подсвечивается в **«Движении»** и блоком **«Ждут проверки»** на вкладке **Разовые** **только в текущем месяце и только с дня проводки** (день шаблона ≤ сегодня по Москве). Другие месяцы периода (прошлые и будущие) в этот блок не попадают. **«Изменить»** — overlay правки месяца; **«Подтвердить»** снимает ожидание за текущий месяц. При наличии таких строк вкладка «Разовые» открывается сама. Клик по назначению ежемес. строки открывает overlay правки месяца. В карточке шаблонов — **Изменить** / **Удалить**.

Банковский синк **не трогает** cash-таблицы. Виртуальные `tx_id`: `cash:o:{id}` / `cash:t:{templateId}:{YYYY-MM}`.

## Плановые денежные операции

Карточка **«Плановые денежные операции»** (под Наличными, сворачиваемая): статья = **форма оплаты (безнал / нал / оба) + категория + название + план/мес**; для безнала — список **контрагентов (фирма + ИНН)**.

Таблицы: `dg_finance_plan_items` (`payment_form`), `dg_finance_plan_item_inns` (`inn` + `name`), `dg_finance_plan_categories`, `dg_finance_plan_overrides`.

- **Безнал** — факт = исходящие банка по ИНН статьи.
- **Нал** — факт = наличные с `plan_item_id` на эту статью. Привязку задают в форме статьи (чекбоксы шаблонов) или в «Наличных» → «Статья плана». Без привязки «Ушло (нал)» = 0. ИНН не обязательны.
- **Оба** — банк + нал.
- В списке статей колонка **«Фактически»** — **итог за период матрицы** (как «Итого»): ушло и **перерасход** / **остаток** относительно суммы планов за те же месяцы; ниже мелко — текущий месяц. У формы с налом — счётчик привязок.
- **▶ / ▼** слева от статьи раскрывает помесячную матрицу план / ушло (банк) / ушло (нал) / итого / перерасход·остаток (как позиции в заказах МС).
- Сверху карточки — **виджеты и графики** (Chart.js, период матрицы / применённые фильтры орг. и дат): KPI «План / Факт / перерасход·остаток / Безнал / Нал / Статей»; столбцы **план vs факт** по месяцам с линией дельты; doughnut **факт по форме оплаты** (`by_payment_form`); горизонтальные бары топ‑10 статей по |перерасход|/|остаток|. Поиск по статьям сужает и список, и дашборд.
- Планы **не** попадают в «Движение» как виртуальные проводки.

Карточка **«Аналитика по месяцам»**: KPI и график Chart.js по банку **+** наличным с `include_chart` (6 / 12 / 24 мес., **текущий год**, **прошлый год**). Фильтры организации, счёта и **источника**. В ячейке **«Чистый поток»** — сумма за окно, **средний месяц** по полным месяцам (текущий недописанный не входит) и **динамика последнего полного месяца к предыдущему** (подписи месяцев). KPI **«Остаток на счетах»** — как «Всего доступно» (расчётные + оценка депозитов); **«Разница»** — изменение остатка за период (помесячная реконструкция; оранжевая линия на графике, правая ось; в tooltip — разница и разбивка). **По умолчанию без внутреннего оборота** (для столбцов вход/исход/чистый поток). Помеченный капитал/займ и дивиденды **всегда** вне графика. Галка **«Не учитывать расход на ИНН 362903774541»** (вкл. по умолчанию, `exclude_chart_inn`) исключает исходящие на этот ИНН из графика/KPI/контрагентов; в «Движении» строки остаются.

Карточка **«Контрагенты»** (под фильтрами): топ доходных («кто платит нам») и расходных («кому платим мы») с долей от суммы; наличные без контрагента группируются как **«(наличные)»** / по назначению. Период / орг / счёт / источник — из **применённых** фильтров; без дат — окно как у графика (`months`). Клик по строке подставляет поиск и направление — дальше «Применить».

Расписание (выкл. по умолчанию) — карточка на `/settings.html`, журнал — `/processes.html` (`task_type=finance_tochka`). Задача идёт на **воркер 2** (`parser-autosync-w2`), параллельно общей очереди МС на воркере 1. Прогон включает включённые ключи Точки, Райфа и Т‑Банка (наличные не синкаются). Частичный сбой одного банка → красный статус и текст ошибок в логе запуска, не «всё ок».
