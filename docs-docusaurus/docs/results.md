**`/results.html`** — просмотр таблицы **`prices`**: что именно сохранил парсер (цена, валюта, SKU, название, время, проект/конкурент). Отсюда оценивают качество [селекторов](/docs/projects/) и решают, нужен ли повторный прогон.

На один `page_id` и на **канонический URL** (`https://` без `www`, без дубля `http://`) хранится **одна актуальная** строка: повторный парсинг **обновляет** запись (SKU/название/цену), а не плодит дубли с разными датами.

## Как читать строку результата

- **Проект** — какой конкурент (см. [Конкуренты](/docs/projects/)).
- **Время** — когда парсер завершил запись (часовой пояс — как настроен на сервере/в БД).
- **Цена / SKU / Название** — извлечённые значения; пустое поле чаще всего означает промах селектора или отсутствие узла в HTML.

## Фильтрация и сортировка

Используйте фильтры по **проекту**, диапазону дат, текстовому поиску (SKU, название, **URL**) — набор зависит от версии. **Сортировка** по колонкам помогает найти последние изменения или самые большие расхождения.

## Действия

- **Повторный парсинг** выбранных строк — после правки селекторов в проекте.
- **Очистка** результатов (глобально или по проекту) — **необратима** в смысле удаления строк из `prices`; используйте осознанно.

## Колонки и поля (ориентир)

Точный набор колонок зависит от версии UI, но логика типична:

| Колонка / поле | Зачем смотреть |
|----------------|----------------|
| **Проект** | Связь с [Конкурентами](/docs/projects/); фильтр «только этот сайт». |
| **Сопоставление** | Есть ли подтверждённая пара; под плашкой — **наш** SKU/название/сайт (ссылка на «Совпадения»). |
| **SKU / артикул** | Качество сопоставления с «нашими» товарами; пусто — проверить селектор SKU. |
| **Цена, валюта** | Сырые значения после Cheerio; неверная валюта — отдельное поле в проекте. |
| **Время** | Порядок прогонов; сортировка по убыванию — последние изменения сверху. |

## Хранение и «устаревание» строк

В [Настройках](/docs/settings/) задаётся **`results_retention_days`**: удаляются **старые** строки `prices`, но **последняя запись по каждому `page_id` сохраняется**. Параллельно на `pages` кэшируются `product_name`, `last_sku`, `last_price`, `last_is_oos` (очередь показывает название без зависимости от истории цен). Страницы `done`/`product` без единой строки в `prices` фоном возвращаются в `pending` для перепарсинга. Перед **очисткой из UI** сделайте выборку или экспорт, если нужна полная история цен.

## Связь с сопоставлением

Для [Сопоставление](/docs/matches/) нужны **актуальные** строки в `prices` по выбранным конкурентам. Если матчинг даёт странные пары — сверьте качество **названий** и **SKU** в результатах.

## API
