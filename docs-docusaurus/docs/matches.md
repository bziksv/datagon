**`/matches.html`** (меню **Парсинг → Сопоставление**) — автомат и ручная стыковка **мой товар ↔ конкурент**. Карта: [Карта панели](/docs/panel-map/). API: `/api/matches` → `routes/matches.js`.

## Доступ

Ключ матрицы — **`matches`**.

| Режим | Что доступно |
|-------|----------------|
| **`hidden`** | HTML и `/api/matches` недоступны |
| **`view`** | Списки / status / log — GET |
| **`full`** | start/stop, confirm/reject/unlink, manual-queue, archive (с **confirm-модалкой**, не `window.confirm`) |

Справочники «Мой сайт» / «Конкуренты» на экране идут через **`GET /api/matches/my-sites`** и **`GET /api/matches/competitors`** (ключ **`matches`**). Не через `/api/my-sites` / `/api/projects`: иначе при `hidden` у «Мои сайты» или «Конкуренты» селекты пустые при открытом сопоставлении.

## Шаги экрана (гайд)

1. **Автомат** — сайт + конкуренты, порог, start / stop / retry; кандидаты **pending**.
2. **Подтверждение** — confirm / reject / unlink / упаковка (`PATCH …/pack`).
3. **Не нашли пару** — промах прошлого прогона (`no_match`) и отклонённые пары (`rejected`). Следующий запуск снова сравнивает `no_match` и снимает строку, если пара нашлась. `rejected` авто не повторяет, пока не нажато «Вернуть в авто».
4. **Архив** — единственный список, который автопрогон пропускает (`match_manual_archive`). Удаление из архива возвращает товар в обычный запуск. В таблице колонка **«Категория»** — корневая категория каталога нашего сайта (Webasyst: дочерние сворачиваются к корню). Фильтр **«Родительские категории»** — множественный выбор с поиском по названию; товар из дочернего раздела попадает к своему родителю. Таблица обновляется по **«Применить»**.

Фильтры внутри шагов — по **«Применить»** / Enter. Не путать с [Конкурентами МП](/docs/marketplaces/).

## Подготовка к запуску

1. В [Мои сайты](/docs/mysites/) выполнен **синк** — в `my_products` есть актуальные строки.
2. В [Результаты](/docs/results/) есть **свежие** `prices` по выбранным конкурентам с типом **товар** (`page_type=product`). Автомат, ручной поиск и resolve SKU **не** берут инфо/категорию/утиль (даже если строка есть в `prices`).
3. В [Настройках](/docs/settings/) заданы разумные **лимиты** нагрузки (если матчинг длинный — уменьшите `batchSize`, увеличьте паузы).

## Параметры задачи (что означают)

| Параметр | Смысл |
|----------|--------|
| **Порог** (`threshold`) | Минимальная уверенность для кандидата; выше — меньше шум, ниже — больше кандидатов на ручную проверку. |
| **batchSize** | Сколько пар обрабатывать за один проход цикла; влияет на нагрузку CPU/БД. |
| **batchPauseMs** / micro-паузы | Паузы между пакетами и микро-паузы внутри длинных циклов — защита от перегрева БД. |
| **Режим / выбор товаров** | «Все», по поиску, по списку id — зависит от формы в UI. Режимы в UI (три шага): **1** строгий SKU (`sku`) → **2** **«По словам v2»** (`name_words_v2`) → **3** **«По SKU v2»** (`sku_v2` — очистка артикула, составные, артикул в названии; из нескольких карточек — по похожести названия). **«По словам v2»** (`name_words_v2`) — то же, плюс вес слова по редкости, слова-пустышки не считаются, `МикроТимп3` = `МикроТимп-3`, `25мм` = `25 mm`, `Grundfos` ≈ `Грундфос`, разные латинские бренды — отказ, лишнее число с одной стороны — штраф (3↔2 — отказ), однобуквенные модификации («П/Г» vs «Г», «Сономед-315 Р» vs «С») тоже различаются, при равном проценте выше карточка с нашим артикулом; в «Совпадениях» под процентом видно, какие слова совпали; кнопка **«спорно»** (или «ещё вариантов: N») открывает окно со всеми подходящими карточками конкурента — наш товар сверху, слова, которых нет в нашем названии, подсвечены, у каждой ссылка, цена и кнопка «Подтвердить эту» / «Выбрать эту и подтвердить», внизу «Ни одна не подходит — отклонить»; синонимы/конфликты слов учатся на подтверждённых и отклонённых парах. Режим «Общий» (`all`) снят с UI. |

## После запуска

1. Откройте [Логи](/docs/processes/) — убедитесь, что задача **в работе** или **завершена**, а не упала с ошибкой.
2. Обновите список кандидатов в разделе сопоставления.
3. Для каждой **pending**-строки: **Подтвердить** (если пара верная) или **Отклонить** (если ложное срабатывание).

## Если «задача уже выполняется»

- `GET /api/matches/status?my_site_id=…` — посмотреть состояние.
- `POST /api/matches/stop` с `{ "mySiteId": N }` — остановить.
- `POST /api/matches/retry-last` — продолжить/повторить последнюю конфигурацию (см. [API](/docs/api/#matches)).

Не запускайте второй матчинг для того же `my_site_id`, пока первый не завершён — сервер вернёт ошибку.

## Ручной разбор кандидатов

- **Pending** — не «ошибка», а ожидание решения: просмотрите пару SKU/названий и контекст цены в [Результаты](/docs/results/) по конкуренту.
- При **Подтвердить** (шаг 2) и ручном confirm (шаг 3) можно задать **коэффициент упаковки**: «У нас упаковка (× N)» или «У нас поштучно (÷ N)» + количество N ≥ 2. Без коэффициента сравнение цен остаётся 1:1. На confirmed — «Сохранить упаковку» без разрыва пары.
- Сопоставимая цена конкурента: `ours` → `цена × N`; `competitor` → `цена ÷ N`. Она же используется в gap и «синк цены от конкурента» на [Мои товары](/docs/myproducts/).
- **Confirmed** — пара участвует в расчётах в [Мои товары](/docs/myproducts/) (колонки конкурента, разрыв цены) согласно логике сервера.
- **Rejected** — ложное срабатывание. Авто эту пару не предлагает снова, пока в «Не нашли пару» не нажато «Вернуть в авто». Постоянный пропуск — «В архив» или **«Товар для маркетов»** (оба на шаг 4, разный `archive_kind`).
- На шаге 3 у «Наш товар» показываются **складская позиция** и **остаток** из `ms_export` (если код найден).
- На шаге 4 колонка **Тип** (`Архив` / `Маркеты`) и фильтр **«Как отправили»**; URL `manual_archive_kind`.
- При **сотнях** pending используйте сортировку/фильтр в UI (если есть) или выгрузку через [`GET /api/matches/list`](/docs/api/#matches) с пагинацией.
- Если один **SKU** на нескольких карточках сайта: в шаге 3 жёлтое предупреждение и кнопка **«Какая пара пристыкована?»** — модалка с кодом/названием очереди и уже подтверждённой пары (чтобы не путать варианты вроде 2,5В Heine и 3,5В Китай). В списке шага 2 код карточки подтягивается **по названию**, а не по первому совпадению артикула.

## Когда снижать порог, а когда повышать

- **Повысить** `threshold`, если много явного мусора в pending — меньше кандидатов, выше точность.
- **Понизить**, если «тихо» и кандидатов мало при заведомо похожих названиях — осторожно, растёт ручная работа.

## API (основное)

- Авто: `POST /start-matching`, `/stop`, `/retry-last`; `GET /status`, `/list`; `POST /confirm` / `/reject` / `/unlink`; `POST /clear-pending` (кнопка «Сбросить ожидающие» — только pending по сайту/конкуренту/типу, с модалкой).
- Ручное: `GET/DELETE /manual-queue`, `POST …/return-to-auto`, `…/archive-all` (`archive_kind`); `GET/DELETE /manual-archive` (`archive_kind`); `POST /manual-match/confirm|relink|archive` (`archive_kind`).
- Вспомогательные: `/prices-search`, `/prices-resolve-sku`, `/product-match-log` (прайс конкурента — только `pages.page_type` = product / без типа).
