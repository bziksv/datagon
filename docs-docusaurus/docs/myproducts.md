Экран **`/my-products.html`** — основная таблица каталога **`my_products`**: что пришло с [Моих сайтов](/docs/mysites/), активность, связь с **МойСклад** (`ms_export`), сравнение с ценами **конкурентов** (если настроены парсинг и сопоставление). Карта: [Карта панели](/docs/panel-map/). API: `/api/my-products` → `routes/myproducts.js`.

## Доступ

Ключ матрицы — **`my-products`** (в меню: «Мои товары (сайты)»).

| Режим | Что доступно |
|-------|----------------|
| **`hidden`** | HTML и `/api/my-products` недоступны |
| **`view`** | Список / stats / fx-rates — GET |
| **`full`** | refresh-one, sync цены с конкурента (одна / bulk), стоп bulk, ручная цена / заморозка (одна / bulk) |

Фильтры и поиск — только по **«Применить»** / Enter (черновик vs применённое). Wide-таблица: горизонтальный скролл **в карточке**, плавающий `thead` (как эталон my-products; не схема shop Ozon/WB/Я.М.).

**Webasyst / модификации:** при синке каждая строка `shop_product_skus` становится **отдельной** записью `my_products`. Поле `source_id` = **id SKU** (модификации), чтобы UNIQUE `(site_id, source_id)` не схлопывал несколько артикулов одной карточки. Поле **`cms_product_id`** = id карточки `shop_product` — его показывают в колонке **«ID / КОД»** и в ссылке «редактировать в Webasyst» (иначе открывалась бы чужая карточка с тем же числом, что и id SKU). После первого синка со старой схемой остаются неактивные «призраки» с прежним `source_id` (= id карточки) — их снимает `cleanupInactiveSkuDuplicates`.

## Структура экрана (обобщённо)

1. **Верхняя панель фильтров** — сайт-источник, активность, связь с МС, аудит сопоставлений, разрыв цены с конкурентом и др. (набор зависит от версии).
2. **Таблица** — строки товара; горизонтальный скролл при большом числе колонок (по эталону [МойСклад](/docs/moysklad/#эталон-списочной-страницы): кнопки `🧩 Столбцы` / `📏 Ширины` / `Свернуть` справа в card-header, поле «Умный поиск» зеркалит основное поле фильтров, шестерёнка в карточке фильтров с auto-discovery новых полей).
3. **Действия по строке** — обновление из источника, подтягивание цены с конкурента (если политика включена), прочие кнопки из UI.
4. **Сортировка** — клик по заголовку столбца; направление и колонка часто **запоминаются на пользователя**.

## Фильтры: зачем каждый

| Фильтр | Практический смысл |
|--------|---------------------|
| **Сайт** | Один источник (`my_sites.id`) или все сразу. |
| **Статус (активность)** | После синка «лишние» позиции могут быть неактивны — см. [главная FAQ](/docs/) п.7. |
| **Связь с МС** | Есть ли соответствие в `ms_export` по нормализованному коду (подробности в [REST API](/docs/api/#my-products)). |
| **Разрыв с конкурентом** | Диапазон отклонения цены; может требоваться курс **USD/EUR** — курсы подтягиваются API (см. `fx-rates` в справке API). |
| **Поиск** | Несколько слов через пробел — по полям товара (как на сервере). |

## Сортировка

- По умолчанию часто используется порядок по **ID с сайта** (возрастание) — уточняйте по подсказке в шапке таблицы.
- Повторный клик по тому же столбцу меняет **направление**.
- Если сортировка «сбрасывается» — проверьте, не открыта ли другая вкладка с тем же пользователем.

## Типовые задачи

### Найти товар по артикулу

Введите SKU (или часть) в **поиск**, при необходимости сузьте **сайт**. Проверьте, не включён ли лишний фильтр (например, только «связанные с МС»).

### Понять, почему нет цены конкурента

Нужны **результаты парсинга** по этому конкуренту и **сопоставление** — без подтверждённой или автоматической связи колонки конкурента могут быть пустыми. Цепочка: [Конкуренты](/docs/projects/) → [Очередь](/docs/queue/) → [Результаты](/docs/results/) → [Сопоставление](/docs/matches/).

### Обновить одну строку из источника

Действие **обновить одну позицию** → `POST /api/my-products/refresh-one` (см. [API](/docs/api/#my-products)).

### Синх. цены с конкурента (Dealmed / Медкомплекс)

- **Одна строка** → `POST /sync-price-from-competitor` (min цена ДМ/МК в RUB минус случайный %; запись в CMS + аудит `comp_sync_*`).
- **По фильтрам** → «Синх. цены по фильтрам» / «Стоп» → bulk API + `#mp-action-log` (план → опрос статуса → итог со счётчиками). Учитываются **серверные** фильтры списка (`match_audit`, сайт, Δ…), не клиентские `tf_*`.
- Автосинк `task: 'price_comp_sync'` — карточка на [Настройках](/docs/settings/) (`auto_sync_price_comp_*`, default **10:00**), журнал на [Активность / Логи](/docs/processes/). Полный синк каталога из CMS — `auto_sync_myproducts_*` / [Мои сайты](/docs/mysites/).

### Наклейки (стикеры)

Колонки с галками после **«Название»** (подпись + краткая подсказка под галкой). Журнал поля — кнопка **«лог»** при наведении (как на «Новые товары»), overlay `#dg-mp-log-overlay`, API `GET /api/my-products/:id/log`.

| Наклейка | Как ставится | Порядок в списке |
|----------|--------------|------------------|
| **Есть РУ** | Авто, если в атрибутах МС есть ссылка РУ и **не** стоит «Нет РУ» | — |
| **Нет РУ** | Вручную; перекрывает «Есть РУ» даже при ссылке | — |
| **Есть в наличии** | Авто по остатку `ms_export.stock > 0` при связи с МС | **В начале** списка |
| **Снят / аналог** | Вручную («Снят с производства/аналог по запросу») | **В конце** |
| **Не поставляется** | Вручную («Не поставляется, предлагаем аналог») | **В конце** |
| **Скидка** | Вручную **только** при активной заморозке цены; при снятии/истечении hold снимается | — |

Ручные флаги: колонки `sticker_*` в `my_products`. Сохранение: `POST /api/my-products/set-sticker`.

**Выгрузка в Webasyst (наклейки + остатки):** задача автосинка `stickers_cms` (карточка «Наклейки и остатки → Webasyst» на `/settings.html`, **03:00** МСК, **воркер 4** / `parser-autosync-w4`). Features `dg_sticker_*`: computed «Есть РУ» / «В наличии» / «Скидка» и ручные флаги (OR по SKU одной карточки). Остаток → `shop_product_skus.count` (или `wa_field_stock_val`): по умолчанию общий `ms_export.stock`; если у сайта на [Мои сайты](/docs/mysites/) заданы **`ms_stock_store_uuids`** — **сумма** по выбранным складам из `ms_export_stock_by_store` (и «В наличии» считается по этой сумме). Полный прогон идёт **пакетами** по ~300 CMS-карточек (`DATAGON_STICKERS_CMS_PRODUCT_BATCH`), чтобы не OOM на ~40k SKU. Без связи с МС count CMS не затираем. После `set-sticker` — точечный догон. Webhook: `POST /api/hooks/stickers-cms-sync` + `X-Datagon-Hook-Token`. Локально: `npm run dev:local` с override CMS site `2`.

### Заморозка своей цены (не синхронизировать с конкурентов)

Иногда цену правят вручную и не хотят, чтобы следующий синк с ДМ/МК её перезаписал.

- Колонка **«Ручн.»** перед «Цена»: замок ставит/продлевает заморозку; у активной — бейдж **«до дд-мм-гггг»** (если ≤ 7 дн. — «до (скоро) …»); после истечения — **«истёк дд-мм-гггг»** (дата не стирается, пока не снять вручную). У ячейки — **лог** изменений заморозки (тот же overlay, что у наклеек).
- **Срок** задаётся один раз селектом «Срок заморозки» (30 / 60 / **90** / 180 дн., в `localStorage`) — не у каждой строки отдельно.
- Можно сразу указать другую цену → запись в CMS + hold; если цена та же — только hold (без CMS).
- **Фильтр «Заморозка цены»:** замороженные / **истекают ≤ 7 дн.** / **срок истёк (разморожены)** / без активной. Список «срок истёк» — чтобы быстро снова заморозить или поменять цену, если цена у конкурента на сайте всё ещё неактуальна. Сортировка «Срок заморозки» + массовое «Заморозить по фильтрам» на этом фильтре.
- **Массово:** «Заморозить цены по фильтрам» / «Снять заморозку по фильтрам» (dry_run → confirm → `#mp-action-log`). Цены в CMS не трогает. Снятие hold также снимает наклейку **Скидка**.
- Пока `price_hold_until > NOW()`, single/bulk/auto competitor sync **пропускает** строку (`skipped_hold` / `409 PRICE_HOLD_ACTIVE`). После срока hold «гаснет» для синка; поля `price_hold_*` остаются до ручного снятия или новой заморозки; `sticker_sale` при этом обнуляется.

## Производительность

Список и **статистика** (`/api/my-products/stats`) кэшируются на короткий TTL — при массовых изменениях цифры могут обновиться с задержкой. При «тяжёлых» запросах в MySQL см. [FAQ гл.](/docs/) п.10.

## Действия по строке (что обычно есть в UI)

| Действие | Когда применять |
|----------|------------------|
| Обновить из источника | Одна позиция «поехала» после правки в БД магазина; не ждите полного синка. |
| Подтянуть цену конкурента | Если уже есть сопоставление и политика позволяет точечный запрос к данным `prices`. |
| Перейти к связанным данным | Зависит от версии: иногда ссылка на результат парсинга или на карточку МС. |

Точные имена кнопок и доступность — по подсказкам в интерфейсе; дублирующие вызовы смотрите в [REST API — My products](/docs/api/#my-products).

## Фильтры «аудит» и отчётность

Фильтры вроде **«разрыв с конкурентом»**, **«нет связи с МС»**, **«неподтверждённое сопоставление»** предназначены для **еженедельного обзора**: сохраните набор фильтров (если UI запоминает) и проходите список пакетами, а не всем каталогом сразу.
