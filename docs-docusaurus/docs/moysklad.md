## С чего начать новому пользователю

1. Убедитесь, что в `config.js` или в переменной окружения **`MS_TOKEN`** задан рабочий токен с правами на чтение нужных сущностей МС.
2. Откройте **МойСклад** и проверьте **статус** последней задачи (не висит ли ошибка с прошлого запуска).
3. При необходимости нажмите **Синхронизация** и дождитесь завершения (индикатор в UI + [Логи](/docs/processes/)).
4. Используйте **поиск** и фильтры, чтобы найти конкретный **код/артикул** и сверить поля с вашей учётной политикой.

## Блоки интерфейса

Страница состоит из **двух карточек**: «Фильтры и действия» и «Выгрузка МойСклад» (карточка с таблицей). Этот же макет — **эталон** для всех новых списочных страниц Datagon, см. правило `.cursor/rules/datagon-list-page-baseline-moysklad.mdc`.

### Карточка «Фильтры и действия»

| Блок | Назначение |
|------|------------|
| Шестерёнка `⚙` справа в заголовке | Открывает дропдаун **«Поля фильтров»** с переключателями: что показывать в форме. Поддерживает **auto-discovery** — новый input с атрибутом `data-dg-ms-filter-field="<key>"` появляется в списке автоматически, даже если разработчик забыл добавить ключ в группы (см. `datagon-table-filter-apply.mdc`, раздел «Авто-обнаружение новых полей»). |
| Кнопка `Свернуть/Развернуть` справа в заголовке | Прячет/показывает только тело карточки фильтров; сохраняется в `localStorage` (`datagon_moysklad_filters_collapsed_v1`). |
| Ряд 1 (форма) | **Умный поиск** (`code`, `name`, `supplier`, `supplier2`; ключи `sku:`, `name:`, `supplier:`, `manager:`, `stock:`; группы через `|`), `ID/КОД`, `Наименование товара`, `Тип`, `Архивные`, `Поставщик`, `Поставщик 2`. |
| Ряд 2 (форма) | `Менеджер`, `Контент-менеджер`, `Остаток от/до`, `Складская позиция`, `На сайте`, `На странице`. **Дубликатов** «табличный/API» вариантов одного и того же поля нет (раньше были `ms-tf-supplier` ↔ `ms-f-supplier` — устранено). |
| Чекбоксы | `Только с остатком > 0`, `Перестали сотрудничать`, `Только с закупочной ценой`. |
| Действия | `Применить` (primary), `По умолчанию` (outline) — далее: `Запустить синхронизацию`, `Остановить`, `Пересчитать остатки комплектов`, `Перестроить кэш связей`, `Обновить`, `Скопировать ссылку`. |
| Подсказка-параграф под кнопками | Видна только когда идёт фоновая задача или сервер прислал реальный `message`. В простое скрыта (никаких заглушек «Ожидание»). |

### Карточка «Выгрузка МойСклад» (таблица)

| Блок | Назначение |
|------|------------|
| Заголовок | Слева в `card-header`: иконка + «Выгрузка МойСклад». |
| Поле «Умный поиск» в шапке | Зеркалит основное поле фильтров (`#ms-f-search`): двусторонняя синхронизация, **Enter** — кликает `Применить`, **Esc** или нативный «×» — очищает оба поля и сразу применяет. На каждое нажатие клавиш серверных запросов нет (правило `datagon-table-filter-apply.mdc`). |
| Кнопка `🧩 Столбцы` | Открывает панель чекбоксов видимости столбцов (источник — массив `MS_COLS`). |
| Кнопка `📏 Ширины` | Ручная ширина каждой колонки в пикселях (тоже из `MS_COLS`); альтернатива — drag за правый край заголовка. |
| Кнопка `Свернуть/Развернуть` | Прячет тело карточки таблицы (заголовок с поиском и кнопками остаётся виден). |
| Таблица | Строки `ms_export`; широкая таблица с горизонтальным скроллом и `sticky`-th под верхним меню. |
| Пагинация | `На странице` / `Найдено: N; страница X/Y; показано: K` / кнопки `Назад / Вперёд` (по 100 строк по умолчанию). |

### Сводка над таблицей

| Карточка | Что считает |
|----------|-------------|
| **Всего в выборке** | Количество строк в текущем фильтре. |
| **Товары / Комплекты** | Раздельно по типу. |
| **Сумма по товарам** | `остаток × закупочная цена` только по строкам `Товар` (`GET /api/ms/stats → inventory_value_products`). |
| **Сумма по комплектам** | То же, но по `Комплект` (`inventory_value_bundles`). Не смешивается с суммой по товарам, чтобы один комплект и его компоненты не попадали в одну цифру. |

## Типовой сценарий сверки с «Моими товарами»

В [Мои товары](/docs/myproducts/) признак **связи с МС** опирается на сопоставление **нормализованных** кодов между `my_products` и `ms_export`. Если связь «плавает»:

- выполните повторный **sync** МС;
- проверьте, что в МС и у вас в источнике **одинаковая логика** артикула (пробелы, регистр нивелируются на сервере — см. API);
- при массовых правках — кэш статистики может задержаться на TTL.

## Если синхронизация не идёт

1. [Логи](/docs/processes/) — не застряла ли предыдущая задача.
2. Токен и лимиты API МС (ошибки 401/403 в логах сервера).
3. `GET /api/ms/status` — вручную через API (см. [документацию API](/docs/api/#moysklad)).
4. После смены токена в конфиге — **перезапуск Node**.

## Колонки `ms_export` (общий смысл)

Набор колонок зависит от версии выгрузки; ориентиры:

| Тема | Что смотреть |
|------|----------------|
| **Код / артикул** | Связь с [Мои товары](/docs/myproducts/) после нормализации. |
| **Тип** | Товар / **комплект** — комплекты часто требуют отдельной бизнес-логики в отчётах. |
| **Остаток, цены** | Сверка с витриной МС; расхождения — часовой пояс и налоги. |
| **«На сайте» / архив** | Фильтры в UI; помогают отсечь неактуальные строки при ручной проверке. |

## Лимиты API МойСклад

У МС есть **rate limit** и размер страницы; в Datagon см. `ms_sync_page_limit` и `ms_sync_delay_ms` в [Настройках](/docs/settings/). При `429` или таймаутах — **увеличьте** паузу, **уменьшите** страницу, не запускайте второй синк, пока первый не завершён.

### Комплекты: состав в кэше и пересчёт остатков

Загрузка списка **`/entity/bundle`** с `expand=components,...` в API МойСклад **нестабильна при большом `limit`** (часто в ответе остаётся только `meta` без `components.rows`). Поэтому при синхронизации список комплектов запрашивается **пакетами не больше 100 строк** на страницу (независимо от `ms_sync_page_limit` для товаров), чтобы в **`ms_entity_details`** попали полные карточки с составом.

Если после обновления Datagon вы всё ещё видите в итоге пересчёта «пропущено: N» почти для всех комплектов — выполните **полный sync** МойСклад ещё раз: старые записи в `ms_entity_details` могли быть сохранены без строк состава. Кнопка «Пересчитать остатки комплектов» при расчёте подтягивает код номенклатуры по `href` компонента (как при полном синке), для этого нужен рабочий **`MS_TOKEN`**.

## API (для автоматизации)

- `POST /api/ms/sync` — старт фона.
- `GET /api/ms/status` — состояние.
- `GET /api/ms/export` — страницы таблицы с query `search`, `type`, `limit`, `offset`.

Полное описание — [REST API — MoySklad](/docs/api/#moysklad).

## Эталон списочной страницы

`/moysklad.html` — **эталон** для всех новых списочных страниц Datagon vanilla. Любая новая страница со списком/таблицей делается **по аналогии** с этой страницей; контракт зафиксирован в правилах:

- `.cursor/rules/datagon-list-page-baseline-moysklad.mdc` — структура двух карточек, кнопки в card-header, шестерёнка с auto-discovery, поиск-зеркало в шапке, единый источник `<X>_COLS` для столбцов/ширин/`<thead>`/`<tbody>`, чек-лист для новой страницы.
- `.cursor/rules/datagon-table-behavior-lock.mdc` — sticky-th, scroll, borders, без разрыва `thead`/`tbody`, пагинация по 100, формат счётчика «Найдено: N; страница X/Y; показано: K».
- `.cursor/rules/datagon-table-filter-apply.mdc` — двухслойная модель состояния (`pending` ↔ applied), применение фильтров **только** по кнопке «Применить» или Enter в поле поиска, auto-discovery новых полей в шестерёнке.
- `.cursor/rules/datagon-ui-baseline-master-lock.mdc` — мастер-лок, перечисляет все правила.

Файлы-референсы (читать при сомнениях):

- `static-html/vanilla/inners/moysklad.inner.html` — разметка двух карточек.
- `static-html/vanilla/inners/moysklad.scripts.html` — IIFE: `filtersCollapse`, `tableCardCollapse`, `columnControls`, `bindHeaderSearchMirror`, `moyskladFilterFieldVisibility`, `renderStatusHint`.
- `static-html/vanilla/inners/moysklad.head.html` — CSS: `.datagon-columns-toolbox`, `.datagon-columns-panel`, `.dg-ms-header-search`, sticky-`th` для wide-таблицы.
- `static-html/vanilla/datagon-vanilla.js` — общая утилита `DatagonFilterFieldsVisibility.init` с auto-discovery.
