Сопоставление
Запуск ищет пары. Ненайденные проверяются снова. Авто пропускает только архив и пары, которые вы отклонили.
Пять блоков на странице
  1. Запуск. Сайт, конкуренты и кнопка «Запустить авто по фильтру» — прогон по каталогу. Пустой поиск значит все активные товары.
  2. Наши товары. Таблица с галочками. Нужна только для кнопки «Запустить по выбранным товарам». Для полного прогона её не трогают.
  3. Совпадения. Найденные пары: подтвердить или отклонить.
  4. Не нашли пару. Промах прошлого прогона. Следующий запуск проверяет эти товары снова и переносит строку в «Совпадения», если пара появилась.
  5. Архив. Единственный список, который авто больше не проверяет. Товар попадает сюда кнопками «В архив» или «Товар для маркетов» (колонка «Тип»).
Гайд Как проходить страницу по шагам

Сначала прогон по SKU. Промах попадает в «Не нашли пару» и на следующем запуске проверяется снова. Из авто товар выпадает только после «В архив» / «Товар для маркетов» или если в «Совпадениях» нажали «Отклонить».

Что подставляется при открытии страницы
  1. Параметры в адресе (query) имеют приоритет: my_site_id, list_my_site_id, list_competitor_id, status, mode, product_search, matches_page, matches_limit и др. Если параметра в URL нет — может подставиться значение из сохранённых фильтров (следующий пункт).
  2. Сохранённые фильтры в браузере (модуль фильтров, localStorage): список «Совпадений», конкурент, умный поиск, статус и лимит — только для тех полей, которых нет в query; сайт запуска по умолчанию — из контекста «Мои товары», если нет my_site_id.
  3. Вид карточек и гайда — в localStorage под префиксом datagon_matches_* (развёрнутость гайда, шагов 1–4, «Мои товары», ширины колонок). На сопоставление товаров не влияет.
  4. Не нашли пару: поиск в прайсе и «Подтвердить вручную» — под строкой по кнопке «Найти по конкуренту». Список зависит от «Мой сайт (список)» и конкурента в «Совпадениях».
Шаг 1
Параметры запуска

Выберите мой сайт (запуск), отметьте конкурентов, при необходимости сузьте набор через умный поиск и пакетные параметры. Режим по умолчанию — «По SKU — строгий отбор». При необходимости затем прогоните «Нормализация + детерминированная строка» или «Нормализация артикула». Нажмите «Запустить авто по фильтру» или отметьте товары в таблице «Наши товары» и запустите по выбранным.

Дождитесь завершения задачи по логам. Затем смените режим на «Только название» или «По словам», снова запустите сопоставление по тому же или расширенному набору — так вы отдельно обрабатываете артикулы и названия, без смешения логики в одном прогоне. «По словам» не штрафует перестановку слов. Ожидающие строки в «Совпадениях» по разным режимам (SKU / название / слова / нормализации) для тех же конкурентов сохраняются; заново снимаются только ожидающие по выбранным конкурентам при режиме запуска «все поля».

В статусе задачи числитель/знаменатель — пары «наш товар × конкурент» (шаги воркера), а не число URL в очереди парсинга прайса.

Шаг 2
Совпадения

В блоке «Совпадения» выберите «Мой сайт (список)» и при необходимости конкурента, отфильтруйте статус «Ожидает», примените фильтры. Просмотрите каждую строку: верные пары подтверждайте, сомнительные или неверные — отклоняйте (эта пара больше не предлагается, пока не нажмёте «Вернуть в авто»).

После полного прохода по результатам SKU вернитесь к шагу 1, переключите режим на название, снова запустите задачу и повторите тот же цикл в этом блоке для новых строк «Ожидает».

Шаг 3
Не нашли пару

В «Не нашли пару» две причины. «Авто не нашло пару» — промах прогона; следующий запуск сравнивает товар снова и снимает строку, если пара нашлась. «Авто-совпадение вы отклонили» — вы отказались от предложенной пары, авто её не повторяет, пока не нажмёте «Вернуть в авто». Колонка «Причина» различает эти случаи. Кнопка «События» — таблица последних событий по товару сразу под строкой.

Используйте те же «Мой сайт (список)» и фильтр «Конкурент» в «Совпадениях» для очереди. Кнопка «Найти по конкуренту» в строке открывает под ней поиск в прайсе, подстановку SKU/названия из результата и кнопку «Подтвердить вручную» — так создаётся запись «Вручную» и строка снимается с очереди. Кнопка «Вернуть в авто» у «отклонили» снова включает товар в авто. У «не нашло» следующий прогон и так проверяет строку; кнопка только убирает её из списка до нового промаха.

Кнопки «В архив» и «Товар для маркетов» переносят ситуацию на шаг 4 (разный тип в колонке «Тип»).

Шаг 4
Архив — авто больше не проверяет

Сюда товар попадает кнопками «В архив» или «Товар для маркетов». Это единственный список, который автопрогон пропускает. Удаление возвращает товар в обычный запуск. Фильтр «Как отправили» и колонка «Тип» показывают Архив или Маркеты.

Описание режимов сопоставления

В селекте по умолчанию выбран «По SKU — строгий отбор» (sku). Сначала закрывайте артикулы одним из режимов SKU; «Общий», «Только название» и «По словам» — отдельно, после SKU.

sku · По SKU — строгий отбор по умолчанию
Артикул = SKU: trim + верхний регистр, без другой нормализации. Совпадает с пунктом селекта «По SKU — строгий отбор (trim + регистр)».
sku_best · По SKU — нормализация + детерминированная строка
Тот же нормализованный ключ, что у sku_norm. Если в прайсе несколько строк с этим ключом, берётся одна и та же («детерминированная»): новее parsed_at, затем стабильный порядок по названию и исходному SKU. Это пункт селекта «По SKU — нормализация + детерминированная строка».
sku_norm · По SKU — нормализация артикула
Ключ: NFKC, верхний регистр, без пробелов/NBSP, тире → ASCII -. Берётся первая строка прайса с этим ключом в порядке выборки (не обязательно та же при повторном запуске, если порядок строк меняется).
all · Общий — SKU, затем название
Сначала строгий SKU, если нет — схожесть названий (~85%). Не замена первому прогону по SKU. В селекте: «Общий — SKU, затем название (не вместо SKU)».
name · Только название
SKU не сравнивается. Схожесть — Левенштейн всей строки: перестановка слов сильно снижает балл. Имеет смысл после прогона по артикулам. Промах не блокирует следующий прогон по SKU.
name_words · По названию — слова
SKU не сравнивается. Те же слова в любом порядке дают около 100%. Окончания почти не режут балл («насос» / «насоса», «водяной» / «водяного», «циркуляционный» / «циркуляционного»). Числа и версии обязательны: «МикроТимп-3» ≠ «МикроТимп-2», «ОТОКОНЦЕПТ-4» ≠ «-3», «насос 25» ≠ «насос 32» — пара не сохранится. Лишнее текстовое слово снижает балл; порог 75%. Запускать после SKU, отдельно от «Только название».
Справка по фильтру и режиму
Как считает сервер и что уходит в API

Режим сопоставления (сервер)

  • По SKU (строгий) — trim + верхний регистр; название не используется. По умолчанию и рекомендуемый первый прогон.
  • SKU нормализация + выбор строки — нормализованный ключ; среди строк с этим ключом — одна по дате парсинга / названию / SKU.
  • SKU нормализация — NFKC, верхний регистр, без пробелов/NBSP, тире → -; первое совпадение в прайсе.
  • Общий — сначала строгий SKU, если нет — название (~85%). Запускать после отдельного прогона по SKU, не вместо него.
  • Только название — без SKU, Левенштейн всей строки. Удобнее после прогона по артикулам. Промах не блокирует следующий прогон по SKU.
  • По словам (name_words) — без SKU. Порядок слов не важен, окончания почти не снижают балл; цифры/версии обязаны совпасть (3≠2). Порог 75% (у «Только название» и «Общий» по-прежнему ~85%). Не заменяет «Только название».

Поле «Умный поиск»

  • Для таблицы «Мои товары» строка поиска уходит в /api/matches/my-products: подстрока ищется в SKU, названии и коде импорта (source_id).
  • Для кнопок «Запустить авто по фильтру» и «Продолжить/повторить» та же строка передаётся как фильтр набора товаров для сопоставления: на сервере отбираются только активные товары вашего сайта, у которых подстрока входит в SKU или название (без source_id). К этому набору затем применяется выбранный режим сопоставления. При «Запустить по выбранным товарам» в задачу попадают только отмеченные в таблице ID; строка «Умный поиск» на состав набора для API не влияет.

Обход конкурентов и их прайсов идёт по очереди; для режимов по названию и по словам на один ваш товар выбирается не более одной лучшей позиции конкурента среди кандидатов не ниже порога.

Продолжить/повторить — новая задача по последней остановленной, сбойной или отменённой (если таких не было — по последней завершённой): подставляются сохранённые параметры и чекпоинт, список товаров снова загружается, но уже сопоставленные с выбранными конкурентами позиции пропускаются (см. в логе «Продолжение: пропущено…»). Счётчики справа и числитель пар «наш товар × конкурент» (знаменатель ≈ ваши товары в задаче × отмеченные конкуренты; не объём очереди парсинга) при продолжении наращиваются с предыдущей задачи. «Новых записей в „Совпадениях“» — только новые строки в БД за этот прогон.

Прогресс опрашивается раз в 1,5 с для выбранного «Мой сайт (запуск)». «Остановить» обрабатывается между товарами, между чанками лога и до пакетной вставки совпадений в БД; один долгий INSERT по сотням строк или загрузка всего прайса SQL всё ещё могут занять секунды без разрыва. При долгом «Остановка задачи…» обновите вкладку — сработает watchdog «нет активности» в БД.
