Автосинхронизация по расписанию
Включить

Ежедневный импорт каталога ваших магазинов (Bitrix / Webasyst) в локальную таблицу my_products (страница «Мои товары»): обходит все источники из «Мои сайты», обновляет SKU, цену и остаток, помечает отсутствующие в источнике как is_active=0. Прогресс и статус — на «Логи фоновых процессов» (раздел «Мои товары»).

Включить

Ежедневный обход API МойСклад: тянет товары и комплекты в локальную таблицу ms_export для страницы «МойСклад» (карточки, остатки, поставщики, цены, теги). Скорость и пакетирование — поля «Лимит страницы» и «Задержка» ниже в настройках МС. Прогресс и статус — на «Логи фоновых процессов» (раздел «МойСклад»).

Включить

После успешного ночного (или ручного) обновления маркетплейсов автоматически пишется снимок для страницы «Проблемы с товарами» (фильтр «есть проблемы», исключить комплекты): дата, слот HH:mm из этого поля, число строк и разбивка по менеджерам / контент-менеджерам.

Включить

Ежедневная авторизация в e-teleport (Huckster) под учёткой из настроек ниже (email / password) и обход магазинов из «Набор магазинов 1» / «Набор 2». Сервис строит матрицы рекомендованных цен (Витрина и РРЦ) для страницы «Huckster (РРЦ калькулятор)»: скачивает товары, считает по правилам и сохраняет снапшот в БД (журнал — logs/huckster-sync.log). Прогресс и статус — на «Логи фоновых процессов» (раздел «Калькуляция Huckster»).

Включить

Ежедневный пересчёт двух метрик дашборда одной задачей:
1) Размер БД по information_schema.TABLES (суммарный объём, данные, индексы, число таблиц рабочей БД p_datagon_ru) — эндпоинт GET /api/processes/db-size, виджет «Размер базы данных».
2) Дисковое пространство: рекурсивный обход корня проекта (`node_modules`, `vendor`, `.git`, `docs-docusaurus` и т.д.) с разбивкой по папкам и объёмом ФС через fs.statfs — эндпоинт GET /api/processes/disk-usage, карточка «Дисковое пространство».
Оба результата кэшируются на сервере (TTL ~5 мин); галка управляет их единым ежедневным пересчётом. Прогресс и статус — на «Логи фоновых процессов» (раздел «Размер БД и диска»).

Включить

Аналог кнопки «↗ В МС: все правки» на странице «Габариты»: для всех позиций с пользовательским замером и заполненным uuid в ms_export отправляет PUT в /entity/{product|bundle}/{uuid}. Журнал — таблица ms_dimensions_log (action sync_ms); прогресс и статус — на «Логи фоновых процессов» (раздел «Габариты МС»).

Включить

Тянет отгрузки entity/demand из МойСклад API за выбранное окно (по умолчанию 90 дней). UPSERT в ms_demand, позиции — в ms_demand_position, резолв до товаров ms_export. Soft-delete для отгрузок, удалённых в МС за тот же период (см. «Продажи МС», фильтр «Удалённые в МС»). Длительность зависит от объёма: на тестовых данных ~8 минут на ~1300 отгрузок за 7 дней; для 90 дней оценочно 1.5–2 часа. Прогресс и финальный статус — на «Логи фоновых процессов» (раздел «Продажи МС»). Можно остановить кнопкой «Остановить» прямо в карточке «Продажи МС».

Журнал замеров габаритов

Журнал хранит историю изменений габаритов товаров/комплектов МойСклад (страница Габариты): кто, что и когда менял в ячейках, и какие значения отправлялись в МС. Автоочистка удаляет записи старше указанного числа дней — раз в 12 часов плюс при старте сервера. По умолчанию 180 дней.
