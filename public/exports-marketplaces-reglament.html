Регламент МП: от поиска товара до поступления на склад

Альмамед Версия 1.0 31.08.2026

Единая последовательная инструкция для сотрудников маркетплейсов. Заменяет три разрозненных документа («поиск на МП», «расширение у действующих», «SellerStats»). Финиш процесса — товар оприходован на складе.

1. Зачем эта инструкция

Раньше сотрудники описывали каждый свой кусок: кто-то витрину, кто-то SellerStats, кто-то работу с действующим поставщиком. Получались обрывы (до таблицы / до оплаты) и разные правила (когда запрашивать РУ, какая таблица, где заканчивается работа менеджера).

Главное правило Один процесс · три входа (A / B / C) · одна таблица новинок · один хвост до склада. Менеджер МП владеет строкой пайплайна от старта до статуса «На складе» (или отказа).

2. Схема процесса (A→Z)

  1. Старт: задача → проверка дубля в реестре → выбор входа A/B/C
  2. Вход: SellerStats или витрина МП или прайс действующего
  3. Поставщик: приоритет канала + чек-лист условий + запрос РУ
  4. Отбор: стоп-факторы + слои спроса L1/L2/L3 + экономика
  5. Таблица новинок: статус «На согласовании»
  6. Гейт руководителя: утверждено / отклонено / частично
  7. Исполнение: счёт → сайт Альмамед → Мой Склад → карточки МП → «Готово к оплате»
  8. Финал: оплата → отгрузка → приёмка → «На складе»

Ветвления только на выборе входа и при эскалациях. После утверждения путь для всех одинаковый.

3. Роли

РольЗона
МП — менеджер МПСквозной владелец строки: вход, поставщик, таблица, координация хвоста, закрытие после приёмки
РУК — руководительГейт ввода в ассортимент; новый поставщик; спорные случаи; правило цен; выгрузка с сайта
КОН — контентАртикулы (если нет), сайт Альмамед, карточки МП
СКЛ — складПриёмка, акты расхождений, оприходование
БУХ — бухгалтерияОплата счёта, платёжное поручение

Эскалация к руководителю обязательна, если

  • новый поставщик (нет истории закупок);
  • запрет продаж на МП при сильном спросе;
  • проблемы с РУ (нет / не бьётся с моделью / просрочено);
  • маржа ниже утверждённого порога;
  • дубль: позицию уже ведёт коллега;
  • срыв поставки после оплаты.

Запрещено Вести три «личных» процесса и три Google-таблицы. Черновик у себя — можно; в работу и на согласование — только единый реестр новинок.

5. Вход A — SellerStats

Когда: нужны цифры продаж/выручки, плановый поиск новинок.
Не когда: уже есть свежий прайс действующего (сначала C); точечная задача «вот ссылка» (B).

  1. Раздел «Аналитика WB + Ozon + ЯМ».
  2. Категория / подкатегория по смыслу задачи (аптека и целевые ветки).
  3. Сортировка по продажам или выручке за 90 и 30 дней (7 дней — только тренд).
  4. Отобрать кандидатов в «Свой список» (буфер).
  5. Зафиксировать бренд, ссылки, продажи/выручку, цену.
  6. Проверить дубль (сайт / Мой Склад / реестр новинок).
  7. Перейти к блоку «Поставщик».
Не делать Выбирать подкатегорию только потому, что «там больше всего товаров» — часто это перегретая ниша.

Скриншоты UI и видео — в приложении B.

6. Вход B — Витрина маркетплейса

Когда: конкретная карточка; проверка полки глазами покупателя; нет доступа к SellerStats.
Не когда: единственный метод массового «что продавать» без цифр; расширение у своего поставщика (C).

  1. Каталог → категория → подкатегория (пример: Ozon → Аптека).
  2. Отобрать товары, которых нет в ассортименте компании.
  3. По карточке зафиксировать: рейтинг, отзывы, число продавцов, мин/макс цену, ссылку.
  4. Усилить оценку спросом (Wordstat; при возможности SellerStats) — см. блок 9.
  5. Перейти к поиску официального поставщика.

7. Вход C — Прайс действующего поставщика

Когда: поставщик уже в работе; нужно расширить матрицу без поиска нового юрлица.
Не когда: на нужные SKU запрет МП или пустой прайс по нише — уходить в A/B.

  1. Запросить актуальный прайс.
  2. Уточнить возможность продажи на МП (в том числе по новым позициям).
  3. Отобрать позиции, которые ранее не закупались.
  4. Проверить спрос (Wordstat + цены конкурентов на МП; желательно сверка с SellerStats).
  5. Сразу в единую таблицу новинок (не в личный файл).

8. Поставщик — чек-лист

Приоритет канала

  1. Действующий (уже в Мой Склад / история закупок).
  2. Официальный: производитель → дистрибьютор / импортёр.
  3. Иначе — эскалация руководителю.
Важно Продавец на карточке Ozon/WB ≠ поставщик. Сначала бренд и официальный канал.

Первый контакт — запросить

  • Прайс или КП по целевым SKU
  • Можно ли продавать на Ozon / Wildberries / другие МП и какие ограничения
  • Регистрационное удостоверение (если товар подлежит) — статус: получено / запрошено / не требуется

Обязательный минимум до статуса «На согласовании»

БлокЧто зафиксировать
КонтрагентНазвание, роль (производитель/дистрибьютор), контакты, «уже наш?»
КоммерцияЦены, MOQ / мин. сумма, срок поставки, оплата, упаковка
МПРазрешено / запрещено / ограничения (РРЦ, квоты)
РегуляторикаРУ (файл или статус запроса), Честный знак — да/нет
КачествоСрок годности при отгрузке, брак/возврат, гарантия, комплектация
ЛогистикаДоставка до нашего склада, кто платит

Молчание поставщика более 3 рабочих дней — сменить статус («нет ответа»), повторить запрос или искать другой канал. Не держать вечно в «ожидании».

После утверждения руководителем

  • Счёт только на утверждённые позиции
  • Актуальные РУ на эти модели
  • Подтверждение комплектации
  • Сверка: счёт ↔ РУ ↔ строка таблицы (расхождение = стоп)

9. Отбор товара — чек-лист

Стоп-факторы (не в «На согласовании»)

  • Уже есть у нас (сайт / Мой Склад) — тот же бренд и модель.
  • Уже в реестре новинок у коллеги («на согласовании» / «в работе»).
  • Письменный запрет МП (без эскалации РУК).
  • Нужно РУ, а его нет и не запрошено.
  • Неясны модель / фасовка / бренд.

Три слоя спроса (вместе)

СлойИсточникЧто смотреть
L1SellerStatsПродажи/выручка за 90 и 30 дней
L2Яндекс.ВордстатЧастотность по модели / запросу
L3Карточка МПРейтинг (ориентир ≥ 4.5), отзывы, число продавцов, мин–макс цена

Для «На согласовании» минимум: L2 + L3. L1 обязателен на входе A; на B/C — желателен (если нет — пометка «L1 н/д, риск выше»).

Экономика

  • Закупочная цена известна
  • Понятен коридор цен на МП
  • Понятен порядок MOQ / суммы первой закупки
  • Черновая маржа не ниже порога руководителя (см. прил. C)

Итог по кандидату

СтатусКогда
На согласованиеНет стоп-факторов, слои и условия собраны
ЧерновикЖдём прайс / РУ / ответ, товар перспективен
ОтказСтоп-фактор или слабые все слои
ЭскалацияСильный спрос, но блок по РУ / МП / марже / новому поставщику

В комментарии к строке: почему берём (1–2 сигнала) · главный риск · вход A/B/C.

10. Единая таблица новинок

Один реестр на всех. Одна строка = один SKU (бренд + модель + фасовка). Личные Google Sheets — только черновик.

Статусы строки

Черновик → На согласовании → Утверждено / Отклонено → В работе → На складе (или Отмена).

Обязательные поля для «На согласовании»

БлокПоля
СлужебныеДата, менеджер-владелец, статус, вход A/B/C
ТоварНаименование, бренд, фасовка, ссылка на Ozon (если есть)
СпросWordstat; SS 90/30 (или «н/д»); мин/макс цена МП; «почему берём»
ПоставщикНазвание, тип (действующий/новый), ссылка на прайс + дата, закупка, MOQ, МП разрешены?, статус РУ, комментарий по условиям

После утверждения в той же строке (или на листе «Контент» / «Исполнение») ведутся: счёт, артикул, цены сайта и МП, штрихкод, даты оплаты / отгрузки / приёмки.

Запрещено Удалять отклонённые строки. Статус «Отклонено» + причина — для антидублей и обучения.

11. Гейт руководителя

  • Утверждено — статус «В работе», дальше блок 12 только по утверждённым SKU.
  • Отклонено — причина в реестре, конец или доработка и повторный заход.
  • Частично — в работу только отмеченные позиции.
Гейт Руководитель смотрит строку только в статусе «На согласовании» с заполненным минимумом. Ориентир ответа: 2–5 рабочих дней (утверждается, см. прил. C).

12. После согласования (до «Готово к оплате»)

Статус строки: В работе. Порядок строгий — без прыжков.

  1. Счёт + РУ + комплектация (МП) — только утверждённые SKU; сверка счёт ↔ РУ ↔ таблица.
  2. Лист «Контент» (МП): цена для сайта Альмамед (по правилу РУК), РУ, артикул (из счёта / с сайта / «присвоить контенту»).
  3. Сайт Альмамед (контент) — позиция размещена, артикул записан.
  4. Выгрузка с сайта (запрос МП → выдаёт РУК) → карточка в Мой Склад (поля — прил. A).
  5. Штрихкод + итоговая цена МП (МП) — без этого контент не стартует карточки МП.
  6. Карточки на МП (контент) → короткая приёмка МП-менеджером.
  7. Отметка «Готово к оплате» (МП) — все гейты выше закрыты, счёт актуален.
Запрещённые прыжки Оплата до карточек МП · Мой Склад до артикула с сайта · карточки МП без штрихкода и цены · позиции в счёте, не утверждённые руководителем.

13. Оплата → отгрузка → приёмка на склад

  1. Оплата: МП передаёт пакет (счёт, ID строк, «карточки готовы», при необходимости ОК РУК) → бухгалтерия платит.
  2. ПП / подтверждение оплаты уходит поставщику; дата оплаты — в реестре.
  3. Отгрузка: ETA, состав = счёту, ТК/доставка; склад предупреждён.
  4. Трекинг срока; при срыве — эскалация.
  5. Приёмка (склад): количество, наименования, брак, комплектация, срок годности, маркировка (если нужна) → оприходование в Мой Склад.
  6. Статус «На складе» ставит МП только после оприходования.

Исходы приёмки

ИсходДействие
Всё сходитсяОприходовать → «На складе»
Недогруз / пересортАкт · претензия поставщику · строку не закрывать полностью
БракАкт · не продавать · возврат по условиям
ИзлишекНе оприходовать без согласования РУК
Финиш регламента Процесс «поиск → склад» завершён на статусе «На складе». Запуск витрины / FBO — по отдельному операционному регламенту МП.

15. Типовые ошибки (не повторять)

  • Считать работу законченной после «внесли в таблицу и ждём».
  • Вести личную Google-таблицу вместо единого реестра.
  • Принимать продавца МП за официального поставщика.
  • Оценивать спрос только по «много отзывов / высокий рейтинг».
  • Выбирать нишу «где больше всего товаров» в SellerStats.
  • Тащить на согласование без статуса РУ и без ответа про МП.
  • Платить до готовности карточек на МП.
  • Считать закупку закрытой по оплате без приёмки на складе.
  • Отгружать, не предупредив склад.
  • Заводить в счёт позиции, которые руководитель не утверждал.

Приложение A. Поля карточки «Мой Склад»

  1. Поставщик
  2. Код / артикул
  3. Единица измерения
  4. НДС
  5. Неснижаемый остаток (по правилу РУК/склада)
  6. Регистрационное удостоверение
  7. Автоматизация цены (по принятому правилу)
  8. Количество в упаковке (если продаётся упаковками)
  9. Отметка «Складская позиция»
  10. Менеджер, который завёл товар
  11. Менеджер сопровождения
  12. Закупочная цена
