Поставщики

Страница /suppliers.html — агрегат по поставщикам (ms_export + dg_supplier_settings). Карта: Карта панели. API: /api/suppliers → routes/suppliers.js — REST API → Поставщики.

Доступ​

Ключ матрицы — suppliers.

РежимЧто доступно
hiddenHTML и /api/suppliers недоступны
viewСписок, сводка, свежесть, выгрузки XLSX, журнал МС — GET; PATCH настроек и POST …/send-ms-order — нет
fullРедактирование ячеек (кроме «Пополнение, дней» — только admin), заказ в МС, экспорт

/api/product/* для карточки товара с закупок идёт под ключ purchase (не suppliers).

Кто попадает в список​

Уникальные ms_export.supplier, у которых есть хотя бы один товар:

  • складская позиция «Да»;
  • не комплект;
  • «перестали сотрудничать» ≠ «Да»;
  • не архив (is_archived = 0).

PK настроек — supplier_key = trim(supplier) в dg_supplier_settings.

Метрики «к закупке»​

  • Позиция «к закупке» (шт): max(0, min_stock МС − stock − in_transit) — только неснижаемый из МС, без override и без формулы.
  • Сумма закупки: need_qty × buy_price по строкам с need_qty > 0.
  • Наполняемость %: в ячейке кол-во SKU с НС>0 / Σ НС / Σ остаток / %; НС на SKU = COALESCE(override, кэш формулы, min_stock МС). Подсветка: <70% красный, 70–90% жёлтый, ≥90% зелёный.

Ссылки «Поставщик» и «Кол-во к закупке» → /purchase.html?supplier=<ключ>&to_buy=1.

Как пользоваться​

  1. Плашка свежести (GET /data-freshness) — каталог МС (moysklad) и продажи (mssales / mssales_full); ok = обновление сегодня по МСК.
  2. Карточка «Команда и закупки» — KPI + диаграмма (GET /analytics); те же фильтры, что у таблицы; метрики переключаются кнопками (Σ к закупке / SKU / остатки / поставщики / заказы МС).
  3. Фильтры (черновик → Применить / Enter; не на каждый input):
    • умный поиск по имени поставщика;
    • привязанный сотрудник (assigned / none / id);
    • «Требуют внимания» — есть к закупке, сумма ≥ мин., нет успешного заказа в МС ≥30 дн. (или никогда);
    • По умолчанию — сброс и сразу apply.
  4. Карточка таблицы: зеркало поиска в шапке, 🧩 Столбцы / 📏 Ширины / Свернуть, пагинация «На странице» (default 100), статус Найдено….
  5. Редактируемые ячейки (PATCH сразу): сотрудник, комментарий, мин. сумма, наполняемость склада/%, авто-рассылка, текст рассылки; «Пополнение, дней» — только username === admin (иначе UI скрыт, PATCH → 403). Авто-«рек. дней на всего поставщика» нет — рек. дни работают на SKU в Закупках.
  6. Выгрузки XLSX — «для поставщика» / «для закупщиков» (GET /export/supplier|purchaser, to_purchase=1).
  7. Заказ в МойСклад — своя confirm-модалка #dg-sp-confirm-overlay (не window.confirm); создаёт черновик purchaseorder (POST /:supplierKey/send-ms-order). После успеха — тост и опционально «Открыть в МС» (та же модалка). Журнал шагов — #dg-sp-ms-order-log-overlay (GET /ms-order-log).

Рейтинг и отсутствие​

  • Рейтинг продаж (90д) — место по выручке отгрузок МС (как ranking анализа поставщиков, все проекты).
  • Счётчики absence_* / chronic / flicker — диагностика из лога нулей за 90 дн.; согласие с предложением — через предлагаемый нес.остаток на закупках.

Автосинк​

Отдельной задачи suppliers нет. Свежесть данных зависит от:

  • moysklad — каталог / остатки;
  • mssales / mssales_full — отгрузки;
  • purchase_formula_cache — кэш формулы (влияет на наполняемость %).

Карточки — на Настройках, журнал — на Активность / Логи.

Связь с другими разделами​

  • Закупки — позиции «к закупке», формула, Пр.→НС.
  • Анализ поставщиков — продажи, отсутствие, ranking.
  • Анализ товаров — решения по SKU.
  • МойСклад — синк каталога; организация заказа — ms_purchase_order_organization_name в настройках.
