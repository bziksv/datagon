Операционный лист

Страница /ops-sheet.html — операционный лист за выбранный год: по каждому месяцу все менеджеры продаж и строка ИТОГО. Источник колонок — вкладка года Google-книги «Операционный лист» (блок продаж, колонки до План). Блоки логистики / складов / маркетов / Прайм пока не перенесены. Карта: Карта панели. API: /api/ops-sheet → routes/opsSheet.js.

Версия синка Planfix — бейдж sync_script на экране (lib/opsSheetPlanfixSyncRevision.js); история — Версионирование скриптов.

Доступ​

Ключ матрицы — ops-sheet.

РежимЧто доступно
hiddenHTML и /api/ops-sheet недоступны
viewПолный свод по всем менеджерам, только просмотр
fullРучные ячейки (PUT /manual) + синк Planfix / маппинг статусов / отмена синка

В отличие от Таблиц менеджеров, здесь нет ограничения «только своя таблица»: любой с доступом видит всех Менеджер по продажам. Архивных показываем в месяце, если есть цифры; пустые архивные строки скрыты.

Автосинк только отчёта 450694 (task: 'ops_planfix', воркер 2) — карточка на Настройках, журнал на Активность / Логи. Полный синк задач — только кнопкой на этой странице.

Как пользоваться​

  1. Выберите год и период Planfix (кнопки месяцев — можно несколько подряд; «Весь год» снимает отдельные). Поиск менеджера — в шапке карточки «Операционный лист». Применить (или Enter в поиске). В адрес: year, month / months=1,3,5, search, при задачах Planfix — q и page. Перейти к месяцу добавляет jump=10 (только прокрутка).
  2. Перейти к месяцу — только прокрутка к блоку «Январь»…«Декабрь» в листе ниже (не фильтр и не синк Planfix).
  3. Жёлтые ячейки — ручной ввод (оклад; премия с прошлыми месяцами): карандаш или клик → правка → Enter / blur сохраняет; Esc отменяет. С октября 2026 премия с учётом заказов считается автоматически по всем отгрузкам месяца (оплата в прошлых месяцах + в текущем). Дата отгрузки: shipped_at, если пусто у статуса «Отгружен» — fallback на paid_at (тот же месяц). Плавающие (оплата в мае, отгрузка в октябре): в таблицах менеджеров выставьте Дату отгрузки в октябре — иначе заказ останется в месяце оплаты. «Премия за текущий месяц» — полная премия по всем продажам месяца (отгруженные и нет, включая переданные от других менеджеров). Иконка i — модалка. До октября 2026 — архив.
  4. Кол-во заявок* в листе — из локальной БД Planfix (постановщик = менеджер продаж): все статусы, кроме исключений. Стрелка у ФИО менеджера раскрывает статусы за месяц: в счёт — обычным цветом, исключённые — серым с пометкой «не вошло»; внизу итог «вошло / не вошло». Рядом Кол-во заявок (с Гугла) — импорт цифр из Google. В панели Planfix строку статуса тоже можно раскрыть — внутри постановщики.
  5. Оплаченные заявки — число строк продаж за месяц, не статус Planfix.
  6. Период Planfix: несколько месяцев — синк заявок идёт помесячно в одной фоновой задаче; отчёт 450694 при мультивыборе — один generate (как «весь год» по UI Planfix). Перед синком в UI отчёта 450694 выставьте период, согласованный с выбором в Datagon, затем Синхронизировать Planfix (заявки + отчёт) или Только отчёт (без повторной выгрузки задач). Пока синк идёт — Остановить. API generate дат не принимает. Если период в Planfix не совпал с Datagon — ошибка в журнале, гистограмма «В отчёте» за выбранный период не затирается. Снимки отчёта хранятся отдельно по году/месяцу (синк 2025 не убивает полный 2024). Годовой generate 450694 — до 30 мин. Весь год (задачи + отчёт) на проде часто 1–1.5 ч; UI ждёт до 3 ч и рвёт только при отсутствии прогресса > 45 мин. Если браузер показал таймаут, а на сервере синк уже done — достаточно обновить страницу (данные уже в БД).
  7. 🧩 Столбцы / 📏 Ширины — видимость и ширины колонок (сохраняются в браузере).

Поиск менеджера применяется только по «Применить» / Enter (или Esc / «×» — очистка и сразу применить). ИТОГО при активном поиске пересчитывается по видимым строкам. Строка менеджера не показывается в месяце, если все суммы, заявки, оплаты и ручные поля нули / пустые.
