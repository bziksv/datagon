График работы

Модуль учёта рабочего времени, отпусков и начислений. Таблицы ws_*, API /api/work-schedule/* → routes/workSchedule.js. Карта: Карта панели.

HTMLКлюч матрицы
/work-schedule.htmlwork-schedule — Мой день / Отдел / Табель (+ экспорт 1С CSV)
/work-schedule-settings.htmlwork-schedule-settings — организации, отделы, сотрудники

В сайдбаре только График работы. «График · настройки» в меню не показывается — вход со страницы графика (ссылка «настройки орг/отделов») или прямой URL. Не путать с глобальными Настройками (/settings.html).

Журнал изменений (ws_audit_log на вкладке «Табель»): хранение 180 дней (app_settings.ws_audit_log_retention_days), автоочистка при старте Node и раз в 12 ч. Для отпусков в ленте показываются даты и тип заявки.

Отделы = специальности (важно)​

Источник истины для списка отделов графика — специальности из Настроек → «Специальности и доступ к разделам» (specialties), не произвольные названия вроде «Продажи».

  • На /work-schedule-settings.html кнопка «Подтянуть группы» → POST /departments/import-specialties: создаёт ws_department с теми же именами, что у специальностей (кроме «Полный доступ»), без привязки к юрлицу, без дублей имён.
  • Правильный отдел продаж в графике — «Менеджер по продажам» (как specialty id 9), а не отдельный «Продажи».
  • Отдел «Продажи» в ws_department — лишний/устаревший (не из списка специальностей). Если сотрудник оказался там (например Юлия Елагина) — перевести в «Менеджер по продажам» и удалить пустой «Продажи» в настройках графика. Ручное «Добавить» отдел с именем вне специальностей не нужно.
  • Дубликаты специальностей (например два «Проект-Менеджер») тоже лучше схлопнуть в Настройках — иначе при импорте появятся два отдела с одним смыслом.

Экраны /work-schedule.html​

Мой день​

  • Статус смены, Старт/Стоп, таймер.
  • Расчёт ЗП за месяц: часы (ЧЧ:ММ), смены (ставки / норма), оклад (накапало + ставка), премия, доплата за стаж (накапало + полная), отпускные/больничные, итого.
  • Клик по чипу оклада — история (GET /employees/:id/salary-history).
  • Календарь месяца; клик по дню → GET /me/day (сегменты, IP).
  • Заявка на отпуск.

Отдел​

  • Все доступные отделы сразу отдельными блоками (свой + head_user_id + ws_department_manage_scope; у бухгалтерии — все). Без переключателя; визуальное разделение между блоками.
  • В каждом блоке матрица сотрудники × дни; клик правит день при can_edit → PATCH /sheet/cell.
  • Листалка месяцев перед названием месяца (кнопки не прыгают).
  • «Кто работает сегодня» / «Открытые смены» — объединение по всем показанным отделам.
  • Согласование отпусков (блок на вкладке). Пункт мегафона в футере (ArchitectUI Notifications): поллинг GET /vacations/pending, красная точка при очереди, тост при новых заявках, список → /work-schedule.html?tab=dept. Видят руководитель (head_user_id) и бухгалтерия.

Табель (бухгалтерия)​

  • Фильтры: умный поиск сотрудника (ФИО / отдел; Enter или «Применить»; зеркало в шапке таблицы), организация, отдел, месяц.
  • KPI: человеко-дни, ФОТ (оценка), число сотрудников.
  • Таблица: ФИО | Оклад (накапало / ставка) | Премия | За стаж (накапало / полная) | Итого (накапало по графику / плановый оклад+премия+стаж за полный месяц) | Аванс | Остаток | Долг | дни 1…31 | Σ.
  • Аванс и Остаток — клик по ячейке. За месяц можно внести несколько сумм, в том числе отрицательных, у каждой свой комментарий (добавить, изменить, удалить). Долг = Итого (накапало) − сумма авансов − сумма остатков. Если долг отрицательный, эта переплата сразу записывается авансом следующего месяца (строка «Переплата с …», её нельзя править вручную — она обновляется из долга исходного месяца). Пишет бухгалтерия: POST/PATCH/DELETE /api/work-schedule/sheet/payouts.
  • Типы дня в ячейке: работа (1 / ½), О отпуск, Б больничный, Отг. отгул (оранжевый фон); в календаре «Мой день» — подпись «отгул».
  • Часы в ячейке — формат Ч:ММ (напр. 4:23, не 4,9). У сотрудников «по часам» в ячейке приоритет Bitcop (продуктивные); наведение — «Bitcop … · Таймер 09:01–18:05 (7:25)» (интервалы внутреннего таймера открытие–закрытие).
  • Ячейки с открытым таймером — светло-зелёное мигание + «▶»; легенда «на работе (таймер)».
  • Клик по дню — правка ставки/часов/типа.
  • Массовая смена (шапка таблицы): включить режим → кликами выбрать дни (Shift+клик — диапазон в строке сотрудника) → снова нажать кнопку → одна форма (тип/ставка/часы) на все выбранные (PATCH /sheet/cells-bulk). Esc / «Отмена выбора» сбрасывает режим.
  • Часы из Bitcop — модалка с периодом (по умолчанию последние 7 дней), опция «только по часам»; пробный прогон → запись продуктивных часов в ws_work_log.hours_bitcop (POST /bitcop/sync-hours). Пустые дни также заполняют hours_worked/rate (source=bitcop). Дни с таймером / ручной правкой / сегментами не затираются — только дополняется hours_bitcop (в ячейке наведение: «Табель» / «Bitcop»). Отпуск/больничный/отгул не трогаются.
  • Автосинк bitcop_hours (воркер 2): по умолчанию 21:00 МСК, окно 7 дней, только pay_type=hourly — карточка на /settings.html, журнал на /processes.html.
  • Тип оплаты сотрудника (pay_type): salary (оклад × только ставки дней type=work / норму месяца) или hourly (ставка ₽/ч × сумма hours_bitcop, продуктивные часы Bitcop; таймер и ручная правка дня в эту сумму не входят). Стаж и индивидуальная премия «фикс по дням» у почасовых считаются от числа дней с часами Bitcop / нормы месяца, не от ставок смен. Доля не выше 1: выход в дни сверх нормы месяца не поднимает оклад, стаж и премию «по дням» выше полной суммы. Исключение — графики 2/2 и 3/3: норма месяца всегда 15 смен, оклад = ставка × (ставки / 15) и растёт после 15-й смены (16-я — доплата). Стаж и премия «по дням» на этих графиках по-прежнему не выше полной суммы месяца. Почасовая оплата (часы × ставка) от этого потолка не зависит. Премия «целиком» (fixed_full) по-прежнему начисляется полностью. Ячейки отпуск / больничный / отгул / командировка в пропорцию оклада и в Σ ставок не входят — это отдельные статьи (vacation_pay, sick_pay, dayoff_pay, business_trip_pay / компенсация).
  • Периоды оплаты (ws_employee_comp, даты с–по): оклад/₽/ч, тип оплаты и правило премии (тоже версионируется). Расчёт ФОТ берёт условия на дату дня из периода; смена премии на карточке не переписывает прошлые дни (старый период получает снимок прежнего правила). Смена в карточке с «Ставка действует с» / форма Периоды (оклад + премия). UI: кнопка Периоды у сотрудника. Будущий период (дата «С» позже сегодня) не меняет текущий оклад на карточке и не удаляется при правке условий «с сегодня» — новый период закрывается днём перед следующим запланированным.
  • Клик по Премии — ручной ввод за месяц (PATCH /sheet/premium → premium_manual). В окне выбор «Целиком» (premium_source=manual, сумма как введена) или «По дням» (premium_source=manual_days: в ячейке доля от отработанных дней, не выше введённой суммы; подпись «полная …»). Если режим ещё не сохранён, для отделов «Менеджер маркетплейсов» и «SEO-специалист» радиокнопка стоит на «По дням»; у остальных отделов — на «Целиком». Уже сохранённый режим при повторном открытии не меняется. «По правилу» снимает ручной ввод.
  • Премии из продаж подтягиваются сами при GET /sheet для отделов с «продаж» в названии (premium_source=sales, сумма = totals.bonus как на Таблицах менеджеров). Кнопка «Обновить из продаж» — принудительный пересчёт (в т.ч. поверх ручных) после новых оплат в журнале.
  • Dry-run / apply payroll, экспорт CSV.
  • Внизу карточки табеля — «Журнал изменений» (кто правил и когда): GET /audit?scope=edits&month=YYYY-MM; свой поиск сотрудника в шапке журнала (Применить / Enter, Esc — сброс) → employee_q, отдельно от фильтра табеля сверху.

Clock и часы​

  • Сегменты в ws_work_log.segments_json (in/out/ms/hours/ip_*).
  • hours_worked — сумма сегментов; в UI длительности — ЧЧ:ММ (не «0.77 ч»).
  • Ставка дня (0 / 0,5 / 1) по порогам часов отдела/сотрудника; короткие куски не обнуляются до 5 мин для отображения часов.
  • Автозакрытие (тик ~15 мин): смена суток МСК → day-rollover на 23:59:59; иначе лимит clock_auto_close_hours → auto-close. Статус needs_confirm. Параллельно закрывается incomplete в CRM (rise_attendance) для сотрудников с crm_user_id.

Связка таймера с CRM Prime​

Источник истины для табеля/ФОТ — Datagon. CRM (crm.prime-ltd.su, виджет «Начать работу» → rise_attendance) — зеркало дашборда.

НаправлениеКак
Datagon → CRMпосле POST /clock/start|stop пишется/закрывается rise_attendance (UTC) через lib/datagonCrmAttendanceSync.js
CRM → Datagonпосле Attendance_model::log_time CRM шлёт POST /api/work-schedule/clock/sync-from-crm (без сессии, заголовок X-Datagon-Clock-Sync)
Конфликт стартовпобеждает более ранний in/check_in по UTC epoch
Конец дняrollover МСК закрывает оба конца

Привязка сотрудника: поле ws_employee.crm_user_id + select «Сотрудник в CRM» на /work-schedule-settings.html (как Bitcop). Автопо ФИО (users.full_name ↔ first_name+last_name staff) при создании и backfill однозначных совпадений. Env CRM: DATAGON_CLOCK_SYNC_URL, DATAGON_CLOCK_SYNC_SECRET; Datagon: DATAGON_CLOCK_SYNC_SECRET (+ доступ к БД CRM через CRM_PRIME_DB_*). Ошибка зеркала CRM не откатывает смену Datagon (crm_sync_error в ответе / тост).

Экраны /work-schedule-settings.html​

Ключ матрицы work-schedule-settings. Обычно full у Бухгалтерии / Полный доступ; табель при этом может быть на ключе work-schedule или открыт через API max.

Порядок карточек:

  1. Организации — селект «какую править» (не фильтрует сотрудников), поля: название, ИНН, TZ, больничный неофиц. ₽/день, стаж (база / шаг / период мес.). Сохранить → inline #dg-ws-set-org-msg. Удаление — своя модалка; 409, если есть сотрудники. Seed при пустой таблице: АЛЬМАМЕД / ВИЛМЕД.
  2. Bitcop — аккаунт (поддомен), API-ключ, метрика часов (productiveTime по умолчанию / activeTime / totalTime). Проверка связи и сохранение в app_settings (ws_bitcop_*). API-ключ at-rest: AES-GCM enc:v1:… при DATAGON_VAULT_KEY (миграция scripts/migrate-bitcop-api-key-encrypt.mjs). Доступ к payroll/Bitcop — флаг специальности can_payroll (не имя «Бухгалтерия»). См. Bitcop Web API.
  3. Отделы — общий справочник (без привязки к юрлицу). «Подтянуть группы» → POST /departments/import-specialties (имена из specialties, без «Полный доступ», без дублей). Карточка отдела (overlay): тип графика 5/2|2/2|3/3|сменный|гибкий, норма дня, пороги ставки 1 / 0,5, лимит отпусков, правило премии stub / fixed / fixed_full, блок «Доступ к другим отделам» (manage_scopes: галка отдела + «правки»). Seed при старте Node (seedDefaultDepartmentManageScopes): «Руководитель склада» → «Склад» / «Делопроизводитель» / «Логистика» (правки); «SEO-специалист» ↔ «Проект-Менеджер» (взаимный просмотр без правок). Отделы «Склад» (2/2) и «Логистика» (3/3) — норма всегда 15 смен.
  4. Сотрудники — вкладки «Работают» и «Уволенные», фильтр орг. в шапке + умный поиск (Применить / Enter, не на каждый input). Колонки: ФИО, Оф (печать, если галка включена), орг, отдел, дата приёма, Стаж, За стаж, Оплата (оклад / по часам), оклад или ₽/ч, личный график/норма/больничный/премия, Bitcop, CRM, переопределения. У уволенных ещё колонка «С» (fire_date). В карточке: тип оплаты, ставка/оклад, привязка Bitcop и CRM Prime, галки «Оф» (official_employment), «Выделить жёлтым» (sheet_row_highlight — на табеле сплошным жёлтым ячейки «Сотрудник», «Итого», «Аванс», «Остаток») и «Не выплачиваем за стаж», поле «С» и кнопка «Уволить» (подтверждение; карточка уходит на вкладку «Уволенные»). «Вернуть» снимает дату. Привязать пользователя — из GET /users-available + обязательный hire_date (однозначное ФИО → авто crm_user_id). История оклада — GET /employees/:id/salary-history. Табель месяца показывает сотрудника, пока fire_date не раньше начала этого месяца.

Производственный календарь РФ — карточка на этой странице + POST /calendar/sync-rf. Маппинг 1С (/1c-map) — в API; экспорт CSV 1С — кнопка на /work-schedule.html (табель).

Организации и сотрудники (модель)​

  • Несколько юрлиц; сотрудник = users + орг + отдел + hire_date.
  • Отделы = специальности (см. выше); не заводить «Продажи» вместо «Менеджер по продажам».
