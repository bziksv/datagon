Мой Склад (товары)

Экран /moysklad.html — работа с таблицей ms_export: данные из API МойСклад, фильтры, фоновая синхронизация, кэш связей / остатки комплектов. Карта: Карта панели. API: /api/ms → routes/moysklad.js.

Доступ​

Ключ матрицы — moysklad.

РежимЧто доступно
hiddenHTML и /api/ms недоступны
viewexport / stats / detail / status — GET
fullsync / stop / rebuild-links-cache / recalc-bundle-stocks

Автосинк каталога — task: 'moysklad' на Настройках (auto_sync_moysklad_*), журнал на Активность / Логи. Неснижаемый остаток в МС — отдельная задача min_stock_export (мастер-выключатель экспорта).

Снимок интерфейса. PNG: npm run docs:capture-screenshots + npm run docs:docusaurus:build. Кадр viewport; без входа — макет /doc-screenshots/moysklad-sample.html. Съёмка.

С чего начать новому пользователю​

  1. Убедитесь, что в config.js или в переменной окружения MS_TOKEN задан рабочий токен с правами на чтение нужных сущностей МС.
  2. Откройте Мой Склад (товары) и проверьте статус последней задачи (не висит ли ошибка с прошлого запуска).
  3. При необходимости нажмите Синхронизация и дождитесь завершения (индикатор в UI + Логи).
  4. Используйте поиск и фильтры, чтобы найти конкретный код/артикул и сверить поля с вашей учётной политикой.

Типовой сценарий сверки с «Моими товарами»​

В Мои товары признак связи с МС опирается на сопоставление нормализованных кодов между my_products и ms_export. Если связь «плавает»:

  • выполните повторный sync МС;
  • проверьте, что в МС и у вас в источнике одинаковая логика артикула (пробелы, регистр нивелируются на сервере — см. API);
  • при массовых правках — кэш статистики может задержаться на TTL.

Если синхронизация не идёт​

  1. Логи — не застряла ли предыдущая задача.
  2. Токен и лимиты API МС (ошибки 401/403 в логах сервера).
  3. GET /api/ms/status — вручную через API (см. документацию API).
  4. После смены токена в конфиге — перезапуск Node.

Колонки ms_export (общий смысл)​

Поле supplier — имя контрагента из карточки МС. Если при синке expand/GET имени временно не удалось, раньше в ячейку попадало [ID:uuid] (это видно на экране Поставщики как «битые» названия). Сейчас парсер не пишет такой fallback; уже накопленные ID чинятся скриптом node scripts/backfill-ms-supplier-id-labels.js (или повторным успешным синком после фикса).

Набор колонок зависит от версии выгрузки; ориентиры:

ТемаЧто смотреть
Код / артикулСвязь с Мои товары после нормализации.
ТипТовар / комплект — комплекты часто требуют отдельной бизнес-логики в отчётах.
Остаток, ценыСверка с витриной МС; расхождения — часовой пояс и налоги.
«На сайте» / архивФильтры в UI; помогают отсечь неактуальные строки при ручной проверке.

Лимиты API МойСклад​

У МС есть rate limit и размер страницы; в Datagon см. ms_sync_page_limit и ms_sync_delay_ms в Настройках. При 429 или таймаутах — увеличьте паузу, уменьшите страницу, не запускайте второй синк, пока первый не завершён.

Комплекты: состав в кэше и пересчёт остатков​

Загрузка списка /entity/bundle с expand=components,... в API МойСклад нестабильна при большом limit (часто в ответе остаётся только meta без components.rows). Поэтому при синхронизации список комплектов запрашивается пакетами не больше 100 строк на страницу (независимо от ms_sync_page_limit для товаров), чтобы в ms_entity_details попали полные карточки с составом.

Если после обновления Datagon вы всё ещё видите в итоге пересчёта «пропущено: N» почти для всех комплектов — выполните полный sync МойСклад ещё раз: старые записи в ms_entity_details могли быть сохранены без строк состава. Кнопка «Пересчитать остатки комплектов» при расчёте подтягивает код номенклатуры по href компонента (как при полном синке), для этого нужен рабочий MS_TOKEN.

API (для автоматизации)​

  • POST /api/ms/sync — старт фона.
  • GET /api/ms/status — состояние.
  • GET /api/ms/export — страницы таблицы с query search, type, limit, offset.

После успешного сохранения ms_export (в конце полного синка) выполняется пакетное обновление dg_product_zero_stock_log за сегодня: только строки со складской позицией «Да», не в архиве, и при этом остаток ≤ 0 или (для кода без дефиса в номенклатуре) остаток строго меньше минимального числового суффикса среди кодов вида <тот же код>-<целое> в той же выгрузке (например 27877-2 и 27877-10 → порог 2 шт. для базы 27877). Импорт отгрузок («Продажи МС», entity/demand) к этому шагу не относится. Затем тем же событием заполняется dg_product_stock_snapshot: по каждому коду в ms_export — одна строка на текущую календарную дату с полем stock (повторный синк в тот же день перезаписывает значение; данные старше product_stock_snapshot_retention_days из настроек Datagon удаляются при синке, по умолчанию 365 дней).

Эталон списочной страницы​

/moysklad.html — эталон для всех новых списочных страниц Datagon vanilla. Любая новая страница со списком/таблицей делается по аналогии с этой страницей; контракт зафиксирован в правилах:

  • .cursor/rules/datagon-list-page-baseline-moysklad.mdc — структура двух карточек, кнопки в card-header, шестерёнка с auto-discovery, поиск-зеркало в шапке, единый источник <X>_COLS для столбцов/ширин/<thead>/<tbody>, чек-лист для новой страницы.
  • .cursor/rules/datagon-table-behavior-lock.mdc — sticky-th, scroll, borders, без разрыва thead/tbody, пагинация по 100, формат счётчика «Найдено: N; страница X/Y; показано: K».
  • .cursor/rules/datagon-table-filter-apply.mdc — двухслойная модель состояния (pending ↔ applied), применение фильтров только по кнопке «Применить» или Enter в поле поиска, auto-discovery новых полей в шестерёнке.
  • .cursor/rules/datagon-ui-baseline-master-lock.mdc — мастер-лок, перечисляет все правила.

Файлы-референсы (читать при сомнениях):

  • static-html/vanilla/inners/moysklad.inner.html — разметка двух карточек.
  • static-html/vanilla/inners/moysklad.scripts.html — IIFE: filtersCollapse, tableCardCollapse, columnControls, bindHeaderSearchMirror, moyskladFilterFieldVisibility, renderStatusHint.
  • static-html/vanilla/inners/moysklad.head.html — CSS: .datagon-columns-toolbox, .datagon-columns-panel, .dg-ms-header-search, sticky-th для wide-таблицы.
  • static-html/vanilla/datagon-vanilla.js — общая утилита DatagonFilterFieldsVisibility.init с auto-discovery.
