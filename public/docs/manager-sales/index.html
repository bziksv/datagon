Таблицы менеджеров

Страница /manager-sales.html — годовой журнал сделок менеджера. Источник колонок — Google-книга «AlmaMed — Отчет по продажам» (вкладки 2019–2026). Калькулятор, листы «Системный» и «Новые товары» сюда не переносились. Карта: Карта панели. API: /api/manager-sales → routes/managerSales.js.

Доступ​

Ключ матрицы — manager-sales. У каждого менеджера своя таблица; чужие строки API не отдаёт (кроме переданных вам и режима can_pick_manager).

Режим / рольЧто доступно
hiddenHTML и /api/manager-sales недоступны
viewСвоя таблица, только GET
fullПравка своей таблицы (POST/PATCH/импорт себе)
Полный доступ / Бухгалтерия / Делопроизводители / adminПереключатель «Таблица менеджера» + свод «Все»; список — только специальность Менеджер по продажам
Планы по годам (запись)Только Полный доступ / Бухгалтерия / admin (делопроизводители — просмотр)

Строки не удаляются: крестик в строке открывает модалку и переносит запись в архив (archived_at). Архив этой же таблицы: кнопка «Архив» в «Фильтрах и действиях» или селект Архив (Скрыт / Только архив / Все строки). В архиве у строки кнопка «Восстановить» (у номера и справа) — она возвращает запись в активные. У каждой строки журнал изменений (иконка блокнота слева от №): кто, когда, поле, было → стало. Кнопка лог на ячейке показывает только это поле; если по нему ничего не меняли — пусто, весь журнал строки не подмешивается.

После колонки Премия — значок ⇄. По клику строка владельца появляется в таблице выбранного менеджера в том же месяце (по дате оплаты). У принимающего может быть своя копия заказа с тем же номером счёта — дубль допустим. У владельца строка остаётся (спокойный фон по получателю, в Передан: «к Екатерине Киланьян»); суммы, % МП. и премия у него по этой строке показываются как 0 и не входят в план. У получателя эта же строка с подписью «от …», плюс своя копия с тем же № счёта тоже подсвечивается и в Передан пишет «от Евгения Клевцова». Колонка Менеджер (сразу после №) показывает, чья это строка. После передачи экран переключается на таблицу получателя и нужный месяц. «Не передан» снимает передачу. Премия на экране — целые рубли.

Чтобы менеджер вёл свою таблицу, ему нужен режим full (режим view запрещает POST/PATCH).

Как пользоваться​

  1. Полный доступ / Бухгалтерия / Делопроизводители: в шапке страницы выберите менеджера — таблица переключается сразу (без «Применить»). «Все менеджеры» — свод. Добавить строку в своде открывает выбор, в чью таблицу писать. Импорт CSV — только когда выбран конкретный человек.
  2. Выберите год и при необходимости месяц, затем Применить. При открытии страницы и по «По умолчанию» стоит текущий месяц. «Все месяцы» — весь год. Месяц берётся из даты оплаты; строки без даты (новые черновики) тоже видны в выбранном месяце.
  3. Добавить строку — пустая запись со следующим № в этом месяце (его выдаёт система, править нельзя). Если у двух строк один № нашего счёта (например отделили НДС), порядковый № одинаковый, строки стоят рядом и подсвечены. Пустой черновик (ещё нет даты, суммы, ссылки) подсвечивается красным, кроме ячейки Условия оплаты. Как только в строке появляются данные, подсветка снимается. На заполненной строке красным подсвечиваются пустые обязательные ячейки (дата, счёт, суммы, НДС, договор, статус, поля закупки). Доставка до нас — на каждого поставщика своё поле, ₽; если доставки не было, поставьте 0 (пустое не считается заполненным). В формуле L — сумма этих доставок. Заполненные импортированные строки без «Условий оплаты» красными целиком не становятся.
  4. Правьте ячейки: суммы — текстовое поле с пробелами тысяч; Счет от ИП или ООО — селект Альмамед / Вилмед / ИП; Наличие договора — Обычный договор / Нет / Договор-Счет; Статус — Заказан у поставщика / Отгружен / Частично отгружен / Возврат средств (ячейка: мягкий жёлтый / зелёный / жёлтый / красный). Дата отгрузки (shipped_at) — при первом переходе в «Отгружен» / «Частично отгружен» ставится сегодня (МСК); можно поправить вручную (нужна для «плавающих» заказов в операционном листе с окт. 2026). № нашего счёта — зелёная отметка, если создан заказ покупателя + счёт + входящий платёж; клик по номеру включает или снимает её, карандаш правит номер. У заголовка колонки ? — подсказка. Ссылка на заказ — кликабельный URL, рядом копировать и карандаш. Ссылка на счёт поставщика — цветная метка с текстом ссылки (клик — подсветка этой закупки: чёрный / синий / оранжевый / зелёный; у нескольких поставщиков цвета независимы), ↗ открывает URL, копировать и карандаш (URL или Склад). У заголовка этой колонки ? — легенда цветов. Сразу после — колонка Комментарии: список сверху, + снизу; формат «Евгения К. — дата — текст», новые сверху; свой — карандаш (правка/удаление в модалке). Далее Отправка вместе: чип вместе · N или V-4802 + V-4810, общий мягкий тон строк одной связки; + связать / клик по чипу — модалка, ввод № нашего счёта другой строки того же года; × — выйти из связки (с подтверждением). Фильтр «Отправка вместе»: только связанные / без связки. Разница / % Р. / % МП. / Премия считаются сами. Одна продажа может иметь несколько закупок: +поставщик под колонкой «Поставщик»; × у имени — убрать закупку (своя модалка подтверждения; единственного поставщика убрать нельзя). В формуле K — сумма закупок, L — сумма доставок.
  5. Планы по годам — кнопка на этой странице открывает модалку: год, план года для всех, пороги % МП. этого года (ступенчатая шкала «если сумма месяца меньше X → Y%», иначе верхний %), строка на каждого менеджера (план года + 12 месяцев). Пустая ячейка плана наследует значение слева. На отпуск уменьшите месяц. Если план менеджера/месяца меньше последнего порога, ступени пропорционально сжимаются. % МП. один на все строки месяца этого менеджера.
  6. Импорт CSV — выгрузка листа Google (Файл → Скачать → CSV) в том же порядке колонок. Сначала пробный прогон (dry_run) — счётчики в #dg-msl-action-log под фильтрами, затем «Импортировать N строк». Только при выбранном конкретном менеджере.
  7. Экспорт CSV — текущий применённый фильтр.

Фильтры (поиск, статус, поставщик, договор, счёт Альмамед/Вилмед/ИП) применяются только по «Применить» или Enter в поиске. «По умолчанию» сбрасывает форму и журнал действий. После применения фильтры пишутся в адрес страницы (year, month=all или номер месяца, поиск, менеджер и т.д.) — ссылку можно скопировать коллеге, он увидит ту же выборку.

Формулы​

  • Разница (как в Google, налог 16% с листа «Системный»):
    net = (сумма без доставки − сумма с запасом) − НДС_сумма, где НДС_сумма = F×G/(G+100) при НДС G>0;
    Разница = net − net×16/100 − сумма доставок до нас
  • % Р. = Разница / (сумма без доставки / 100)
  • Премия = Разница / 100 × % МП
  • % МП. — не колонка для ввода. Итог суммы без доставки за месяц даты оплаты сравнивается с порогами этого года (модалка «Планы по годам»). Сумма плана: сначала месяц менеджера, затем его год, затем план года для всех, затем 3 300 000 ₽.

Если формулы в живой Google-таблице другие — править только lib/managerSalesCalc.js.

Связь с графиком работы (премия в ФОТ)​

Итоговая премия месяца менеджера (GET /api/manager-sales → totals.bonus, на экране целые ₽) может уйти в табель графика:

  1. Сотрудник в /work-schedule-settings.html должен быть в отделе «Менеджер по продажам» (импорт специальностей), с тем же user_id, что в журнале.
  2. На /work-schedule.html → Табель → месяц: премии подтягиваются автоматически при загрузке листа; кнопка «Обновить из продаж» — принудительный пересчёт.
  3. API: GET /api/work-schedule/sheet (auto) и POST …/premium-from-sales (force) → premium_manual + premium_source=sales (lib/managerSalesMonthBonus.js, как totals.bonus).

Ручная правка одной ячейки «Премия» в табеле — PATCH /api/work-schedule/sheet/premium. Подробнее: График работы.
