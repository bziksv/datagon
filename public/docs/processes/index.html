Активность / Логи

В меню: «Активность/Логи» → /processes.html. Ключ матрицы: processes. Экран — сводка и журнал, не место правки лимитов (они в Настройках). Карта: Карта панели.

Снимок интерфейса. PNG: npm run docs:capture-screenshots (с входом — живая панель; без — макет /doc-screenshots/processes-sample.html) и npm run docs:docusaurus:build. Кадр — viewport. Съёмка.

Журнал активности (верх страницы)​

Карточка «Журнал активности» (#dg-activity-hero): лента login / logout / page / click / ui. Свои фильтры и пагинация; не зависит от выбора «За день (МСК)» ниже. Сворачивание — localStorage datagon_processes_activity_journal_collapsed_v1. Данные: GET /api/activity/events. Без manage-users блок пустой/ошибка при запросе.

Когда смотреть этот экран​

СитуацияЧто искать
Кнопка «Синк» нажата, UI не меняетсяБлок МойСклад или глобальный синк — завершилась ли задача, нет ли ошибки.
Долгий матчингБлок Сопоставление — прогресс или зависание.
Парсинг «висит»Очередь / автообход — не застрял ли воркер.

Что обычно показывает экран (по блокам)​

  • За день (МСК) — единый выбор календарной даты для трёх блоков ниже: «Синхронизация МойСклад», «Автосинхронизация по расписанию», «Сопоставление товаров». По умолчанию — сегодня; доступно 14 дней (включая сегодня) через <input type="date"> или быстрые чипы «Сегодня / Вчера / −2 …». Активити-журнал не зависит от этого выбора — у него свои фильтры. Поллинг сводки на каждые 3 секунды работает только в режиме «сегодня»; на любую другую дату он останавливается, чтобы не дёргать сервер ради историчных данных.
  • Глобальная синхронизация — массовый прогон по всем включённым источникам «Мои сайты»; длительность зависит от объёма и sync_* в Настройках. Не запускайте параллельно с тяжёлыми ручными операциями на той же БД без окна обслуживания.
  • МойСклад — фоновый POST /api/ms/sync: статус смотрите здесь и через GET /api/ms/status. Под блоком — архив шагов в БД за выбранный день: dg_ms_sync_log за этот день (поле moyskladPersistedLogs в GET /api/processes/overview). Сортировка журнала — последние шаги сверху (DESC по id), чтобы свежие записи были видны без скролла. «Текущая сессия (память процесса, до 30 строк)» отдаётся только для «сегодня» — память процесса не различает дат.
  • Автосинхронизация по расписанию — секции только из autoSync.sections (lib/datagonAutoSyncRegistry.js → AUTO_SYNC_TASKS, сейчас 21 задача: myproducts, moysklad, ms_orders, marketplaces_ozon/wb/ym, huckster, np_ms_enrich, np_crm_notify, db_size, dimensions, min_stock_export, mssales, mssales_full, purchase_formula_cache, medmarket, medmarket_fill, price_comp_sync, network_prices, finance_tochka, ops_planfix). Не путать МойСклад: каталог с Продажи МС. У раздела: вкл/выкл, время МСК, extras, запуски за день (auto_sync_runs), бейдж расписание/вручную, кнопка «Лог» (полный message; для dimensions — ещё ошибки из журнала габаритов; для min_stock_export — GET /api/processes/min-stock-export-errors). У running — строка «Сейчас: …» из autoSync.tasks_live. Расписание правится на /settings.html.
  • Парсинг / очередь — worker.js и таблица pages.
  • Сопоставление — последняя matching_jobs за день для my_site_id.
  • Остановить МС (если доступно в UI) — POST /api/ms/stop (ключ API moysklad).

Чеклист диагностики (кратко)​

  1. Зафиксировать время нажатия кнопки и имя процесса на экране.
  2. Обновить логи через 15–60 с — часть задач пишет прогресс пакетами.
  3. Открыть логи сервера за тот же интервал (stack trace, MySQL deadlock).
  4. Для МС/матчинга — вызвать статус через REST API и сравнить с UI.
  5. Если задача «бессрочная» — остановка через API (МС/матчинг) или рестарт воркера/Node по политике эксплуатации.

История автозапусков (auto_sync_runs)​

Строки вроде moysklad — running | старт: … | финиш: - означают: запись в БД создана при старте задачи из расписания/ручного «Запустить сейчас», а finished_at ещё не проставлен. Обычно после завершения синка появится финиш и статус completed / failed.

Если финиш так и не появился после рестарта Node (деплой, pm2, падение процесса), старая строка могла остаться «висеть»: сервер не вызывает finish для уже мёртвого процесса. После обновления Datagon при следующем старте такие running без даты финиша закрываются со статусом interrupted и пояснением в message; записи старше 24 часов в running дополнительно закрываются фоном как failed. Имеет смысл сверить реальное состояние синка на МойСклад и в логах Node.

Срок хранения завершённых строк (finished_at не пустой) задаётся в Настройках — карточка «Журнал запусков автосинхронизации» (auto_sync_runs_retention_days, по умолчанию 180 дней). Автоочистка выполняется при старте сервера и каждые 12 часов; активные running без финиша не удаляются.

Как не путать процессы​

  • Очередь страниц (pages) — это URL конкурентов, не строки my_products.
  • Глобальный синк — массовая операция по всем источникам; может конкурировать по БД с пользовательскими действиями — планируйте время окна.

Если кажется, что «всё сломалось»​

  1. Обновите страницу логов через 10–30 с.
  2. Проверьте консоль сервера Node (stderr) — часто там stack trace, которого нет в UI.
  3. Для МС и матчинга — эндпоинты статуса в REST API.
