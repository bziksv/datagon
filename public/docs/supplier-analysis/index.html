Анализ поставщиков

Страница /supplier-analysis.html — сравнение продаж (отгрузки МойСклад) за период с таким же предыдущим окном, остатки и оборачиваемость. Карта: Карта панели. API: /api/supplier-analysis → routes/supplierAnalysis.js — REST API → Анализ поставщиков.

Доступ​

Ключ матрицы — supplier-analysis.

РежимЧто доступно
hiddenHTML и /api/supplier-analysis недоступны
view / fullВсе эндпоинты — только GET (overview, ranking, highlights, products, export, …). Записей в БД с экрана нет

Не путать с Поставщиками (закупки / заказ в МС) и с Конкурентами парсинга.

Источники данных​

  • Каталог SKU — тот же отбор, что на /suppliers.html (sqlSupplierProductWhere): складская «Да», не комплект, не «перестали сотрудничать», не архив.
  • Ключ поставщика — supplier, иначе supplier2 («Поставщик 2»), см. supplierEffectiveSql.
  • Продажи — ms_demand / ms_demand_position (applicable=1, не удалённые). Привязка: прямой ms_export.code или комплект через dg_bundle_components (у комплектов часто пустой supplier). Цифра в UI МС может быть выше, пока отгрузка не попала в синк Продаж МС.
  • Остаток ₽ — Σ stock × stockCost (после полного синка МС); иначе закупочная с карточки.
  • Отсутствие — эпизоды нуля из dg_product_zero_stock_log (lib/datagonSupplierAbsenceProfile.js). На этом экране — диагностика (долгие / частые короткие); «рек. дней на всего поставщика» / кнопки «Применить» нет. Рек. дни на SKU идут в формулу на Закупках.

Как пользоваться​

  1. Плашка свежести (GET /data-freshness) — каталог МС + продажи (как на поставщиках).
  2. Фильтры (черновик → Применить / Enter; dirty → «Применить •»):
    • период продаж: 30 / 90 / 180 / 365;
    • «новым на складе», дней: 14 / 30 / 45 / 60 (new_stock_days);
    • проекты отгрузок: все или только выбранные (project_mode / project_uuids; default UI — selected; список из GET /projects);
    • поиск по имени поставщика;
    • на странице: 50 / 100 / 200.
  3. По умолчанию — сброс фильтров и сразу apply. CSV — GET /export по текущим применённым фильтрам (UTF-8 BOM, сортировка по attention_score).
  4. Карточка «Сводка за период» — KPI (/overview: выручка, маржа, Δ%, поставщики, без продаж, падающие, остаток ₽), блоки highlights (/highlights: нужна проверка / лучшие по выручке / сильный рост + chronic/flicker absence), графики, раскрываемая расшифровка продаж (/sales-breakdown).
  5. Карточка таблицы «Поставщики: остатки и оборачиваемость» — ranking (/ranking): зеркало поиска, 🧩 Столбцы / 📏 Ширины / Свернуть, пагинация. Клик по №/имени — деталь поставщика (/products modes: absence, stale, new, weak); клик по «SKU складская» / «SKU всего» — соответствующие списки SKU. Ссылка «Закупки» → /suppliers.html.

Фильтр проектов влияет на выручку, маржу и Δ; остатки и каталог SKU от проектов не зависят.

Сигналы и пресеты​

  • Залежалые — остаток > 0, 0 продаж за период, не новинка.
  • Новые на складе — остаток > 0, первый положительный снимок в пределах new_stock_days.
  • Слабые — есть продажи, но sales_qty < 25% медианы по поставщику.
  • Отсутствие: долгий ≥14 дн.; частый короткий ≥3 эпизода со ср. длиной ≤3.
  • Query focus (all|develop|problem) — для подсветок/портфеля на API; согласие с предложением по НС — только через Закупки.

Автосинк​

Отдельной задачи supplier-analysis нет. Нужны moysklad (каталог/остатки) и mssales / mssales_full (отгрузки). Журнал — на Активность / Логи.

Связь с другими разделами​

  • Поставщики — закупки, заказ в МС, настройки сотрудника.
  • Закупки — формула, рек. дни SKU, Пр.→НС.
  • Анализ товаров — решения lifecycle по SKU.
  • Продажи МС — источник отгрузок.
