Мои товары

Экран /my-products.html — основная таблица каталога my_products: что пришло с Моих сайтов, активность, связь с МойСклад (ms_export), сравнение с ценами конкурентов (если настроены парсинг и сопоставление). Карта: Карта панели. API: /api/my-products → routes/myproducts.js.

Доступ​

Ключ матрицы — my-products (в меню: «Мои товары (сайты)»).

РежимЧто доступно
hiddenHTML и /api/my-products недоступны
viewСписок / stats / fx-rates — GET
fullrefresh-one, sync цены с конкурента (одна / bulk), стоп bulk, ручная цена / заморозка (одна / bulk)

Фильтры и поиск — только по «Применить» / Enter (черновик vs применённое). Wide-таблица: горизонтальный скролл в карточке, плавающий thead (как эталон my-products; не схема shop Ozon/WB/Я.М.).

Webasyst / модификации: при синке каждая строка shop_product_skus становится отдельной записью my_products. Поле source_id = id SKU (модификации), чтобы UNIQUE (site_id, source_id) не схлопывал несколько артикулов одной карточки. Поле cms_product_id = id карточки shop_product — его показывают в колонке «ID / КОД» и в ссылке «редактировать в Webasyst» (иначе открывалась бы чужая карточка с тем же числом, что и id SKU). После первого синка со старой схемой остаются неактивные «призраки» с прежним source_id (= id карточки) — их снимает cleanupInactiveSkuDuplicates.

Снимок интерфейса. PNG: npm run docs:capture-screenshots + npm run docs:docusaurus:build. Кадр viewport; без входа — макет /doc-screenshots/myproducts-sample.html. Съёмка.

Структура экрана (обобщённо)​

  1. Верхняя панель фильтров — блок «Каталог» (сайт, статус, МС, валюта, остаток…) + «Применить» / «По умолчанию» / «Скопировать ссылку». Секции «Заморозка цены» и «Цены и конкуренты» (Δ / синк цены с ДМ·МК) — каждая со своим Свернуть/Развернуть (localStorage); в шестерёнке «Поля фильтров» — только каталог и сортировка. Синк каталога с CMS — по расписанию на Настройках / Активность, ручных кнопок на экране нет.
  2. Таблица — строки товара; горизонтальный скролл при большом числе колонок (по эталону МойСклад: кнопки 🧩 Столбцы / 📏 Ширины / Свернуть справа в card-header, поле «Умный поиск» зеркалит основное поле фильтров).
  3. Журнал изменений (карточка под таблицей) — кто и когда менял наклейки / скидку / заморозку. Фильтры: сотрудник, поле, сайт, период, SKU; «Применить» / пагинация 100; API GET /api/my-products/log + /log/actors. По строке по-прежнему «лог» у поля → GET /api/my-products/:id/log.
  4. Действия по строке — обновление из источника, подтягивание цены с конкурента (если политика включена), прочие кнопки из UI.
  5. Сортировка — клик по заголовку столбца; направление и колонка часто запоминаются на пользователя.

Фильтры: зачем каждый​

ФильтрПрактический смысл
СайтОдин источник (my_sites.id) или все сразу. Список грузится из GET /api/my-products/sites (достаточно права Мои товары, страница «Мои сайты» не нужна).
Статус (активность)После синка «лишние» позиции могут быть неактивны — см. главная FAQ п.7.
Связь с МСЕсть ли соответствие в ms_export по нормализованному коду (подробности в REST API).
ВалютаRUB / USD / EUR — серверный отбор (currency=), вместе с остальными полями блока «Каталог» после «Применить».
Разрыв с конкурентомДиапазон отклонения цены; может требоваться курс USD/EUR — курсы подтягиваются API (см. fx-rates в справке API).
ПоискНесколько слов через пробел — по полям товара (как на сервере).

Сортировка​

  • По умолчанию часто используется порядок по ID с сайта (возрастание) — уточняйте по подсказке в шапке таблицы.
  • Повторный клик по тому же столбцу меняет направление.
  • Если сортировка «сбрасывается» — проверьте, не открыта ли другая вкладка с тем же пользователем.

Типовые задачи​

Найти товар по артикулу​

Введите SKU (или часть) в поиск, при необходимости сузьте сайт. Проверьте, не включён ли лишний фильтр (например, только «связанные с МС»).

Понять, почему нет цены конкурента​

Нужны результаты парсинга по этому конкуренту и сопоставление — без подтверждённой или автоматической связи колонки конкурента могут быть пустыми. Цепочка: Конкуренты → Очередь → Результаты → Сопоставление.

Обновить одну строку из источника​

Действие обновить одну позицию → POST /api/my-products/refresh-one (см. API).

Синх. цены с конкурента (Dealmed / Медкомплекс)​

  • Одна строка → POST /sync-price-from-competitor (min цена ДМ/МК в RUB минус случайный %; запись в CMS + аудит comp_sync_*).
  • По фильтрам → «Синх. цены по фильтрам» / «Стоп» → bulk API + #mp-action-log (план → опрос статуса → итог со счётчиками). Учитываются серверные фильтры списка (match_audit, сайт, валюта, Δ…).
  • Автосинк task: 'price_comp_sync' — карточка на Настройках (auto_sync_price_comp_*, default 10:00), журнал на Активность / Логи. Полный синк каталога из CMS — auto_sync_myproducts_* / Мои сайты.

Наклейки (стикеры)​

Колонки с галками после «Название» (подпись + краткая подсказка под галкой). Журнал поля — кнопка «лог» при наведении (как на «Новые товары»), overlay #dg-mp-log-overlay, API GET /api/my-products/:id/log.

НаклейкаКак ставитсяПорядок в списке
Есть РУАвто, если в атрибутах МС есть ссылка РУ и не стоит «Нет РУ»—
Нет РУВручную; перекрывает «Есть РУ» даже при ссылке—
Есть в наличииАвто по остатку ms_export.stock > 0 при связи с МСВ начале списка
Снят / аналогВручную («Снят с производства/аналог по запросу»)В конце
Не поставляетсяВручную («Не поставляется, предлагаем аналог»)В конце
СкидкаВручную: акционная цена + срок (sale_price / sale_until) → сразу в CMS; в модалке выбор — вернуть цену до скидки или оставить скидочную после срока (restore_on_end / sale_price_before). Выбор важен, если нет остатка МС (маржа) и нет конкурента; иначе после срока цена может уйти туда сама. Наклейка гаснет по sale_until. Приоритет над заморозкой и маржой, пока акция активна. На Альмамед: Feature dg_sticker_sale + dg_sticker_sale_until (дд-мм-гггг). Журнал по ячейке «Скидка» показывает всю постановку и снятие: галку, акционную цену, срок, цену до скидки, «вернуть после скидки» и откат цены.—

Ручные флаги: колонки sticker_* в my_products. Сохранение: POST /api/my-products/set-sticker.

Выгрузка в Webasyst (наклейки + остатки + цены): задача автосинка stickers_cms (карточка «Наклейки, остатки и цены → Webasyst» на /settings.html, 03:00 МСК, воркер 4 / parser-autosync-w4). Features dg_sticker_*: computed «Есть РУ» / «В наличии» / «Скидка» и ручные флаги (OR по SKU одной карточки); срок акции — varchar dg_sticker_sale_until (дд-мм-гггг). Остаток → shop_product_skus.count (или wa_field_stock_val): по умолчанию общий ms_export.stock; если у сайта на Мои сайты заданы ms_stock_store_uuids — сумма по выбранным складам из ms_export_stock_by_store (и «В наличии» считается по этой сумме). Приоритет цены SKU: (1) активная акция «Скидка» (sale_price / sale_until) → эта цена на сайт; (2) иначе активная заморозка price_hold_until → цену не трогаем; (3) иначе при остатке > 0 и тирах маржи (price_margin_json) — только от «Закупочная цена» карточки МС (buyPrice в ms_entity_details). Если закупочной нет, цену не пишем: себестоимость отчёта «Остатки» (ms_export.stock_cost / колонка buy_price) и «Цена продажи» не подставляются: saleRub = round(buy / (1 − %/100)) → валюта карточки. Полный прогон — пакетами по ~300 CMS-карточек (DATAGON_STICKERS_CMS_PRODUCT_BATCH). Без связи с МС count/цену CMS не затираем. После успешного прогона — снапшот «закупка > конкурента». После set-sticker / set-sale — точечный догон. Webhook: POST /api/hooks/stickers-cms-sync + X-Datagon-Hook-Token.

Заморозка своей цены (не синхронизировать с конкурентов)​

Иногда цену правят вручную и не хотят, чтобы следующий синк с ДМ/МК её перезаписал.

  • Колонка «Ручн.» перед «Цена»: замок ставит/продлевает заморозку; у активной — бейдж «до дд-мм-гггг» (если ≤ 7 дн. — «до (скоро) …»); после истечения — «истёк дд-мм-гггг» (дата не стирается, пока не снять вручную). У ячейки — лог изменений заморозки (тот же overlay, что у наклеек).
  • Свой остаток МС: блок только если у сайта заданы склады (ms_stock_store_uuids) и сумма по ним > 0 — синк с конкурента не пишется (skipped_own_stock / 409 OWN_MS_STOCK_BLOCK). Без привязки складов общий ms_export.stock не блокирует (сателлиты вроде Вилмед). В «Ручн.» — бейдж «МС», под «Цена» — «блок: остаток МС». Не ручная заморозка: при нуле по складам блок снимается сам.
  • Пустая цена конкурента при остатке 0: если есть подтверждённая связка Dealmed/Медкомплекс, но ни у одного нет цены > 0, остаток МС 0 и своя цена > 0 — синк пишет 0 в CMS и в my_products (cleared_no_competitor). Нет связки, заморозка или акция — цену не снимаем.
  • Закупка > конкурента: красная карточка на /my-products.html, если в снапшоте есть позиции с остатком, где закупка МС выше минимума ДМ/МК более чем на 1% (цена конкурента — сопоставимая, с упаковкой). Снапшот пересчитывается после синка «Наклейки, остатки и цены → Webasyst» (stickers_cms) и по кнопке «Обновить». В списке — ссылки на наш сайт / конкурента; колонка «Сопоставление» открывает окно: кто/когда подтвердил, правка упаковки (PATCH /api/matches/:id/pack) и «Разорвать» (POST /api/matches/unlink, с модалкой подтверждения); колонка «МС» открывает полную карточку МойСклад (GET /api/ms/detail/:uuid, как на /moysklad.html). Упаковка/разрыв пишутся сразу, снапшот алертов не пересчитывается автоматически — пометка «есть правки», Δ % по «Обновить».
  • Срок задаётся один раз селектом «Срок заморозки» (30 / 60 / 90 / 180 дн., в localStorage) — не у каждой строки отдельно.
  • Можно сразу указать другую цену → запись в CMS + hold; если цена та же — только hold (без CMS).
  • Фильтр «Заморозка цены»: замороженные / истекают ≤ 7 дн. / срок истёк (разморожены) / без активной. Список «срок истёк» — чтобы быстро снова заморозить или поменять цену, если цена у конкурента на сайте всё ещё неактуальна. Сортировка «Срок заморозки» + массовое «Заморозить по фильтрам» на этом фильтре.
  • Массово: «Заморозить цены по фильтрам» / «Снять заморозку по фильтрам» (dry_run → confirm → #mp-action-log). Цены в CMS не трогает. Снятие hold не снимает акцию «Скидка» — у неё свой sale_until.
  • Пока активна Скидка или price_hold_until > NOW(), competitor sync пропускает строку (skipped_hold / 409 SALE_ACTIVE / 409 PRICE_HOLD_ACTIVE). По истечении sale_until галка sticker_sale снимается автоматически.
  • Скидка (UI): галка открывает форму цены + срок (дни из селекта «Срок заморозки») → POST /api/my-products/set-sale (цена только в выбранный SKU + sale_price/sale_until; догон Features на карточке Webasyst — без переписи цен соседних артикулов).

Производительность​

Список и статистика (/api/my-products/stats) кэшируются на короткий TTL — при массовых изменениях цифры могут обновиться с задержкой. При «тяжёлых» запросах в MySQL см. FAQ гл. п.10.

Действия по строке (что обычно есть в UI)​

ДействиеКогда применять
Обновить из источникаОдна позиция «поехала» после правки в БД магазина; не ждите полного синка.
Подтянуть цену конкурентаЕсли уже есть сопоставление и политика позволяет точечный запрос к данным prices.
Перейти к связанным даннымЗависит от версии: иногда ссылка на результат парсинга или на карточку МС.

Точные имена кнопок и доступность — по подсказкам в интерфейсе; дублирующие вызовы смотрите в REST API — My products.

Фильтры «аудит» и отчётность​

Фильтры вроде «разрыв с конкурентом», «нет связи с МС», «неподтверждённое сопоставление» предназначены для еженедельного обзора: сохраните набор фильтров (если UI запоминает) и проходите список пакетами, а не всем каталогом сразу.
